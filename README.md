**Transcription is not the end goal — it's step one.**

Drop in an hour-long interview and get back: a transcript with speaker labels,
a ready-to-paste YouTube package (5 title options, hook + summary description,
viewer-oriented chapter timecodes, key-question timecodes, tags), article drafts
in five formats, an insights brief, a book-pipeline draft, and an EDL cut list
for your video editor. Everything runs locally — audio never leaves your machine,
the LLM is local (LM Studio), cloud is opt-in on your own key.

## Why not MacWhisper / Whisper Transcription / etc.?

Those tools do transcription excellently. Whispered does transcription **and
then keeps going**: the transcript becomes a YouTube package, five article
drafts, an insights brief, a book pipeline, and an EDL timeline — all in one
run, with one-click presets. The second differentiator is locality: no
subscription, no upload, no rate limits. The native whisper stack lives
outside the app bundle so you can swap the Metal build without a reinstall.

## Features

### Library
Every transcription is auto-saved to SQLite with full-text search (FTS5).
Reopen any recording with all its generated artifacts intact. One-click
presets chain the whole pipeline: pick a file, choose *Full*, collect
everything.

### Queue & Recorder
Batch-process a folder, or record directly from the microphone — both feed
the same pipeline.

### Transcript view
Built-in audio/video player synced to the transcript. Speaker labels from
`pyannote.audio`, with in-app rename. 9 export formats: TXT, TXT+timestamps,
SRT, VTT, JSON, Markdown, HTML, DOCX, PDF.

### YouTube package
5 title options, a hook + summary description, viewer-oriented chapter
timecodes (gaps ≤ 7.5 min), key-question timecodes, and tags — generated by a
local LLM from the full transcript. Optional cloud provider (your key) on the
same tab.

### Content tools
- **Articles** — blog post, FAQ, listicle, summary, social posts
- **Chat** — ask questions about the transcript
- **Insights** — auto-chapters, action items, key moments
- **Book pipeline** — multi-step draft from any long recording
- **Cut / EDL** — tick segments, export a timeline for your video editor
- **Transcript cleanup** — LLM-assisted filler removal and coherence pass

### UI
Dark / light themes, RU / EN localization, drag-and-drop, animated progress
timeline, toast notifications. The production workspace uses a labelled,
collapsible sidebar, a task-focused Library, full-height Queue and Recorder
pages, a category-based Settings dialog, and a shared operation bar that is
hidden while idle. The opt-in Live workspace adds asynchronous readiness
checks, real ScreenCaptureKit target discovery (Zoom is prioritised), an
incremental dual-source transcript, and privacy-safe collapsible diagnostics.

To render the current UI reference gallery without user data:

```bash
QT_QPA_PLATFORM=offscreen .venv/bin/python tools/render_ui_gallery.py --check
```

## Architecture notes

Four decisions that shaped the codebase — not a feature catalogue.

**Transcription runs in a child process, not a thread.**
`whisper.cpp` is a C extension; cooperative cancellation via `threading.Event`
does not interrupt a running C call. The fix: spawn a fresh process with
`multiprocessing.get_context('spawn')`, relay progress over a `Queue`, and
`terminate()` / `kill()` on cancel. One-click Cancel *actually* cancels.

**A single narrow contract: `Segment(start, end, text, speaker)`.**
Every consumer — the player, the exporters, every LLM prompt — works with a
list of `Segment` objects. The transcription engine is behind that contract.
Swapping whisper.cpp for a different engine (Parakeet, GigaAM) is a
one-import change; the rest of the codebase is untouched.

**The native whisper stack lives outside the app bundle.**
`~/Library/Application Support/Whispered/lib` holds pywhispercpp and the
Metal-compiled dylibs. Updating the whisper.cpp build — or switching CPU →
Metal — does not require rebuilding `Whispered.app`.

**17 prompts in Markdown, zero prompts in Python.**
Every LLM task (`yt_titles.md`, `chapters.md`, `blog_post.md`, …) is a plain
Markdown file loaded at runtime via `core.prompts.load_prompt`. Rewording a
prompt, tightening a constraint, or A/B testing tone is a text-file edit —
no code change, no redeploy.

## Honest limitations

- **Engine:** transcription is whisper.cpp only. The architecture is
  engine-agnostic (`Segment` contract), but alternative backends are not
  yet shipped.
- **LM Studio & parallel requests:** sending several long LLM jobs
  simultaneously can cause the server to stop responding. The insight pipeline
  already works around this by running requests sequentially; other tabs don't
  yet. Workaround: `lms server stop && lms server start`.
- **Platforms:** macOS is the primary target (Metal, `.app` build). Linux
  AppImage works but is less battle-tested. Windows is not supported yet —
  see [ROADMAP.md](ROADMAP.md).
- **UI correctness:** covered by 292 unit tests + headless smoke check (no
  crash). Pixel-level layout is verified manually.

## Quick start

**macOS**

```bash
./setup-mac.sh   # compile whisper.cpp with Metal, download base model
./run-mac.sh
```

**Linux (Fedora / Ubuntu)**

```bash
./setup.sh       # compile whisper.cpp (CUDA / CPU), download base model
./run.sh
```

Build a standalone `.app`:

```bash
.venv/bin/python build.py
```

Build a Linux AppImage:

```bash
appimage/build-appimage.sh
```

For AI features, install [LM Studio](https://lmstudio.ai), load any chat
model, and start the local server (`lms server start`). Whispered picks it up
automatically. Transcription, diarization, and export work without it.
