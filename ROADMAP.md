# Дорожная карта развития Whispered

Цель: довести интерфейс и функциональность Whispered до уровня платных аналогов
(MacWhisper Pro, Descript, Otter.ai, superwhisper, Notta), сохранив главное
преимущество — **полностью офлайн-работу без подписок**.

Документ написан как набор технических заданий для ИИ-агентов по разработке.
Каждая задача самодостаточна: содержит контекст, затрагиваемые файлы, шаги
реализации и критерии приёмки.

---

## 1. Правила для ИИ-агентов (читать перед любой задачей)

### 1.1. Архитектура проекта (текущее состояние)

| Слой | Модули | Назначение |
|---|---|---|
| Точка входа | `main.py` | Запуск QApplication, тема qdarktheme |
| UI | `ui/main_window.py` (окно, header-bar, вкладки), `ui/transcript_view.py`, `ui/ai_panel.py`, `ui/article_view.py`, `ui/batch_panel.py`, `ui/book_panel.py`, `ui/file_selector.py`, `ui/model_downloader.py`, `ui/icons.py` | Виджеты PyQt6 |
| Ядро | `core/lm_client.py` (OpenAI-совместимый клиент LM Studio), `core/ai_worker.py` (QThread для AI-задач), `core/prompts.py`, `core/logger.py`, `core/book_batch_worker.py` | Фоновая работа |
| Движки | `transcriber.py` (whisper.cpp, отдельный процесс), `diarizer.py` (pyannote), `text_processor.py`, `article_generator.py`, `batch_processor.py`, `book_pipeline.py` | Обработка |
| Сервис | `config.py` (dataclass `Config` → `~/.whisper-fedora/config.json`), `utils.py` (модели, языки, GPU), `exporters.py` (txt/srt/vtt/json/md), `lm_studio_manager.py` | Инфраструктура |
| Промпты | `prompts/*.md` | Шаблоны для LLM |

Ключевые типы данных: `TranscriptionResult` и `Segment` (поля `start`, `end`,
`text`, `speaker`) в `transcriber.py`.

### 1.2. Обязательные правила

1. **Офлайн прежде всего.** Никаких облачных API, телеметрии, обязательного
   интернета. Сетевые вызовы допустимы только к локальному LM Studio
   (`config.lm_studio_url`) и для скачивания моделей по явному действию
   пользователя. **Исключение:** облачный API (OpenAI-совместимый или
   Anthropic) допускается только как опционально выбранная пользователем
   возможность конкретной функции (генерация тайм-кодов «ключевых вопросов»
   на вкладке YouTube), и только после явного ввода API-ключа. По умолчанию
   провайдер — `lmstudio`, поведение не меняется; телеметрии по-прежнему нет.
   См. `core/ai_provider.py`.
2. **Не блокировать UI.** Любая операция дольше ~100 мс — в `QThread`
   (см. образец `core/ai_worker.py`) или в отдельный процесс (см.
   `transcriber.py`). Связь с UI — только через сигналы Qt.
3. **Поддержка отмены.** Каждая длительная операция должна иметь метод
   `cancel()` и корректно завершаться в `MainWindow.closeEvent`
   (см. `ui/main_window.py:51`).
4. **Настройки — через `Config`.** Новые параметры добавлять полями dataclass
   в `config.py` со значениями по умолчанию; загрузка старых конфигов уже
   фильтрует неизвестные поля — обратная совместимость сохраняется
   автоматически.
5. **Стиль кода.** Python 3.10+, type hints, докстринги как в существующих
   модулях, логирование через `core.logger.get_logger(__name__)` в
   библиотечном/UI-коде. `print()` допустим только внутри
   `if __name__ == "__main__":` и в самостоятельных CLI-скриптах, которые
   не импортируются приложением (`build.py`, `setup_diarization.py`,
   `zoom_to_blog.py`, `test_whisper.py`). Цветовая
   палитра UI: фон `#2a2a2a`, рамки `#3a3a3a`, акцент `#6366f1`, текст
   `#e0e0e0` (до выполнения задачи 2.1 — копировать из соседних виджетов).
6. **Кроссплатформенность.** Linux (основная), macOS — обе поддерживаются
   и проверяются (`setup.sh`/`run.sh`, `setup-mac.sh`/`run-mac.sh`).
   Windows пока не поддерживается на практике: нет setup/run-скриптов,
   CI не проверяет эту платформу. Код старается не создавать барьеров
   (пути — через `pathlib`/`os.path`, директории данных — по образцу
   `utils.get_models_dir()`), но реальная поддержка Windows — отдельная
   будущая задача, а не текущее состояние.
7. **Зависимости.** Новые пакеты добавлять в `requirements.txt` с
   закреплённой минимальной версией; тяжёлые/опциональные зависимости
   (как pyannote) — импортировать лениво с понятным сообщением об ошибке.
8. **Проверка.** Минимум: `python -m py_compile` всех изменённых файлов и
   запуск `python main.py` со смоук-проверкой сценария задачи (где доступен
   дисплей). Для нового кода без Qt-зависимостей — pytest-тесты в `tests/`.
9. **Одна задача — один коммит/PR.** Не смешивать рефакторинг с фичами.
   Формат сообщений: `feat: ...`, `fix: ...`, `refactor: ...` (как в истории).

## Этап 2. Улучшение интерфейса (UX уровня Descript/MacWhisper)

### Задача 2.1. Встроенный аудиоплеер с синхронизацией транскрипта

Флагманская фича всех платных аналогов: слушаешь запись — текущий сегмент
подсвечивается; кликаешь по сегменту — плеер перематывается.

**Что сделать.**
1. Создать `ui/player_widget.py` на `QMediaPlayer` + `QAudioOutput`
   (`PyQt6.QtMultimedia`, входит в зависимость PyQt6; при недоступности
   мультимедиа-бэкенда — скрывать плеер, не ронять приложение):
   - кнопки play/pause, перемотка ±10 с, слайдер позиции, текущее время /
     длительность (`utils.format_duration`), регулятор скорости
     (0.5×–2× через `setPlaybackRate`), громкость;
   - сигнал `position_changed_sec(float)`;
   - метод `seek_to(seconds: float)`.
2. Встроить плеер над `TranscriptView` в `MainWindow`; источник — файл,
   выбранный в `FileSelector` (`self._source_filepath`). Для видео звук
   играть как есть (QMediaPlayer умеет), видеодорожку не показывать.
3. В `TranscriptView`:
   - хранить соответствие «сегмент → диапазон позиций в QTextEdit»
     (список `(start_pos, end_pos, segment)` заполняется при рендере);
   - слот `highlight_at(seconds)` — найти сегмент по `seg.start <= t < seg.end`,
     подсветить фон (`QTextCharFormat`, цвет — `accent` с прозрачностью),
     снять подсветку с предыдущего, автоскролл к сегменту, если он вне
     видимой области;
   - клик по сегменту (через `cursorForPosition` в `mousePressEvent` либо
     anchor-ссылки на таймстампах) → сигнал `seek_requested(float)`.
4. Соединить сигналы в `MainWindow`. Подсветку обновлять не чаще 5 раз/с.

**Критерии приёмки.**
- [x] Подсветка следует за воспроизведением без подвисаний UI на записи 1ч+.
- [x] Клик по сегменту перематывает плеер на `seg.start`.
- [x] Скорость и громкость работают; пауза/продолжение не сбивают подсветку.
- [x] Без установленного мультимедиа-бэкенда приложение работает как раньше
      (плеер скрыт, в лог — warning).

### Задача 2.2. Редактируемый транскрипт

**Проблема.** `TranscriptView` — read-only. В платных аналогах транскрипт
правится на месте, а правки попадают в экспорт и в AI-обработку.

**Что сделать.**
1. Режим редактирования в `TranscriptView`: кнопка-переключатель «Edit» в
   шапке виджета (рядом с Timestamps).
2. В режиме правки `QTextEdit` становится editable; по выходу из режима —
   распарсить текст обратно в сегменты. Чтобы парсинг был надёжным,
   в режиме правки рендерить строго одну строку на сегмент
   (`[HH:MM:SS.mmm] Speaker: текст`); таймстампы и метки спикеров защищать
   валидацией при выходе (нераспознанные строки приклеивать к предыдущему
   сегменту).
3. Правки писать в `self._result.segments[i].text` — тогда экспорт
   (`exporters.py`), копирование и AI-панель автоматически получают
   отредактированный текст; убедиться, что `full_text` пересобирается.
4. Поиск и замена: панель по `Ctrl+F` (поле поиска, «заменить», «заменить
   все», счётчик совпадений, подсветка всех вхождений жёлтым).
5. Undo/redo штатными средствами QTextEdit в пределах сессии правки.

**Критерии приёмки.**
- [x] Исправленный текст уходит в экспорт всех форматов и в AI-панель.
- [x] Таймстампы и спикеры не теряются после цикла «править → сохранить».
- [x] `Ctrl+F` ищет по транскрипту, «заменить все» работает.
- [x] Случайная порча строки таймстампа не роняет приложение.

### Задача 2.4. История транскрипций (библиотека)
