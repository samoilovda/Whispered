## 1. Что такое продукт (контекст для агента)

**Whispered** — privacy-first десктоп-приложение (PyQt6) для транскрипции
аудио/видео и генерации контента полностью офлайн:

- **Транскрипция**: whisper.cpp (`pywhispercpp`), отдельный процесс с поддержкой
  отмены; ускорение Metal / CUDA / ROCm.
- **Диаризация**: pyannote.audio (опционально, требует HF-токен).
- **AI-постобработка**: локальный LM Studio (OpenAI-совместимый API) — чистка
  текста, статьи, саммари, главы, YouTube-метаданные, соцсети, книжный пайплайн.
- **Видео-режим**: монтаж по транскрипту (`video_edit.py`, `timeline_export.py`).
- **Прочее**: запись с микрофона, батч-обработка, история, чат с транскриптом,
  экспорт txt/srt/vtt/json/md/docx/html, локализация RU/EN, AppImage-сборка.

Архитектура по слоям описана в `ROADMAP.md` §1.1 и соответствует коду:
`main.py` → `ui/*` (виджеты) → `core/*` (воркеры QThread, LM-клиент, логгер,
конфиг-инфраструктура) → движки в корне (`transcriber.py`, `diarizer.py`,
`article_generator.py`, …). Ключевые типы: `TranscriptionResult`, `Segment`
в `transcriber.py`. Конфиг — dataclass `Config` → `~/.whisper-fedora/config.json`.

## 3. Находки аудита

### 3.1. Критичность: высокая

**H1. Линт в CI не блокирует сборку.**
`.github/workflows/ci.yml` содержит `ruff check ... || true` — любые ошибки
линтера игнорируются. Фактическое состояние: **936 нарушений** (E,F,W без
E501/E402/F401), из них 880 автофиксируемых (в основном W293
пробелы-в-пустых-строках), а также 3 голых `except:` (E722) и
2 неиспользуемые переменные (F841).

**H2. HF-токен хранится открытым текстом.**
`Config.save()` пишет `hf_token` в `~/.whisper-fedora/config.json` без
`os.chmod(0o600)`. Токен читается в `diarizer.py:78` и
`ui/model_downloader.py`. Для privacy-first продукта это репутационный риск.

**H3. Двойная система вывода: `print()` против логгера.**
Существует централизованный `core/logger.py`, но в коде 195 вызовов `print()`
(частично — легитимные CLI-блоки `__main__`, частично — отладочный вывод в
рабочих модулях). Диагностика у пользователей непредсказуема.

### 3.2. Критичность: средняя

**M1. `ui/main_window.py` — 1284 строки.**
Окно совмещает: header-bar, управление вкладками, оркестрацию воркеров,
`closeEvent`-отмену, переключение режимов pipeline. Следующий кандидат на
распил — вынести оркестрацию задач в контроллер/презентер, оставив в окне
только layout и сигналы.

**M2. Тесты не покрывают движки.**
Покрыты: exporters, config, i18n, history, json_utils, llm_text,
youtube_description, timeline_export, video_edit, workers, utils. Не покрыты:
`transcriber.py` (586 строк), `article_generator.py` (677), `text_processor.py`
(478), `diarizer.py`, `batch_processor.py`, `zoom_to_blog.py` (513),
`lm_studio_manager.py` (418). Coverage в CI не измеряется.

**M3. Документация рассинхронизирована.**
- `ROADMAP.md`: 0 из 63 чекбоксов отмечены, при этом задачи 1.2 (settings
  dialog), 1.3 (тесты+CI), 2.1 (плеер), 2.4 (история), 2.6 (локализация),
  3.1 (запись), 3.3 (чат) **фактически реализованы** — файлы существуют.
- `REFACTOR_INSTRUCTIONS.md`, `VIDEO_MODE_INSTRUCTIONS.md`,
  `YOUTUBE_DESCRIPTION_PLAN.md` — рабочие планы уже выполненных задач.
- Корень содержал ни одного `README.md` — точка входа для новых контрибьюторов
  отсутствовала (`Description.md`/`APP_DETAILS.md` дублируют друг друга на
  русском и английском, но ни один не читается как README).

**M4. Зависимости не зафиксированы.**
`requirements.txt` содержит только `>=`-границы (PyQt6>=6.6.0 и т.д.), lock-файла
нет. Сборка AppImage и окружение разработчика могут разъехаться.

**M5. Дублирование настроек LM Studio.**
В `Config` два независимых URL: `lm_studio_url` и `book_lm_url` (оба по
умолчанию `http://localhost:1234/v1`), плюс `book_model_name`,
`book_temperature` — параметры книжного пайплайна живут отдельно от общих
AI-настроек. При добавлении третьего пайплайна дублирование вырастет.

**M6. 69 широких `except Exception`.**
Для Qt-приложения частично оправдано (нельзя ронять event loop), но в движках
(транскрипция, LM-клиент) широкий перехват маскирует реальные причины сбоев.
Требуется ревизия: где перехват легитимен — логировать через логгер с
`exc_info=True`; где нет — сузить тип.

### 3.3. Критичность: низкая

- **L1.** В CI нет проверки типов (mypy/pyright), хотя правило §1.2.5 ROADMAP
  требует type hints.
- **L2.** Игнор F401 (неиспользуемые импорты) в линте скрывает мёртвые импорты.
- **L3.** Windows отсутствует в CI-матрице и в инструкциях запуска
  (есть `run.sh`, `run-mac.sh`; `run-win` нет), хотя ROADMAP §1.2.6 заявляет
  поддержку трёх ОС.
- **L4.** Корневые CLI-скрипты (`zoom_to_blog.py`, `book_pipeline.py`,
  `test_whisper.py`) смешаны с движками в корне пакета — стоит развести
  `engines/` и `scripts/`.
- **L5.** `models/ggml-base.bin` (141 МБ) лежит в рабочей копии — корректно
  игнорируется git, но `setup.sh` и документация должны явно указывать, что
  модели скачиваются, а не поставляются.

### 3.4. Что в порядке (не трогать без причины)

- Тестовый прогон: 199 passed за 0.46 с, без GPU/сети/дисплея — эталон для
  новых тестов.
- Изоляция транскрипции в отдельный процесс с отменой — правильное решение,
  сохранять паттерн.
- `Config.load()` фильтрует неизвестные поля — обратная совместимость конфига.
- Локализация: en/ru по 175 ключей, полная синхронизация.
- Правила для агентов в `ROADMAP.md` §1 — актуальны, следовать им.

## 4. План работ для ИИ-агента (по приоритету)

Каждая задача = один коммит/PR (правило §1.2.9). После каждой — `pytest`
зелёный и smoke-запуск `python main.py`, где доступен дисплей.

### Задача A. Включить линт по-настоящему (H1)
1. `ruff check --fix` для 880 автофиксируемых нарушений (W293/W291/F541).
2. Исправить вручную: 3 × E722 (заменить на конкретные исключения или
   `except Exception` с логированием), 2 × F841.
3. Убрать `|| true` из ci.yml; убрать F401 из ignore и почистить импорты.
4. Добавить `ruff.toml` (или `[tool.ruff]`), чтобы конфиг линта жил в репо,
   а не в командной строке CI.
- **Приёмка:** `ruff check .` — 0 ошибок локально и в CI; CI падает при новых.

### Задача B. Защитить токен (H2)
1. В `Config.save()` после записи: `os.chmod(CONFIG_FILE, 0o600)` (на POSIX).
2. Рассмотреть `keyring` как опциональную зависимость: если доступен —
   хранить токен в системном хранилище, JSON использовать как fallback.
3. Убедиться, что токен не попадает в логи (проверить `core/logger.py` и все
   места логирования конфига).
- **Приёмка:** права файла 600; grep по логам не находит токен.

### Задача C. Унифицировать логирование (H3)
1. Ревизия всех 195 `print()`: в модулях-движках и воркерах заменить на
   `logger.info/debug/error`; CLI-блоки `if __name__ == "__main__"` оставить.
2. Правило в ROADMAP §1.2: «`print()` разрешён только в `__main__`-блоках».
- **Приёмка:** `grep -rn '^\s*print(' --include='*.py' . | grep -v venv`
  находит только `__main__`-блоки и `scripts/`.

### Задача D. Актуализировать документацию (M3)
1. В `ROADMAP.md` отметить `[x]` фактически выполненные задачи (проверять по
   коду, не по памяти: наличие файла + smoke).
2. Выполненные планы (`REFACTOR_INSTRUCTIONS.md`, `VIDEO_MODE_INSTRUCTIONS.md`,
   `YOUTUBE_DESCRIPTION_PLAN.md`) перенести в `docs/archive/`.
3. Написать нормальный `README.md`-первый-экран: что это, скриншот, установка
   на Fedora/macOS, ссылка на ROADMAP. `Description.md` удалить или заполнить.
- **Приёмка:** в корне остаются README, ROADMAP, APP_DETAILS, TESTING;
  чекбоксы ROADMAP соответствуют коду.

### Задача E. Зафиксировать зависимости (M4)
1. Сгенерировать `requirements.lock` (`pip freeze` из чистого venv) или
  перейти на `uv`/`pip-tools` (`requirements.in` → компиляция).
2. CI и `build-appimage.sh` ставят из lock-файла.
- **Приёмка:** повторная установка из lock даёт идентичное окружение; CI зелёный.

### Задача F. Поднять покрытие движков (M2)
1. Добавить `pytest-cov` в requirements-dev, шаг coverage в CI (без порога
   на первом этапе — только отчёт).
2. Тесты на чистую логику движков с моками subprocess/LM-клиента:
   `text_processor.py`, `article_generator.py` (разбор ответов LLM),
   `batch_processor.py` (очередь/состояния), парсинг вывода whisper в
   `transcriber.py`.
3. Целевой порог после первой итерации: ≥60% по не-UI модулям, затем ratchet.
- **Приёмка:** отчёт coverage в CI; новые тесты не требуют GPU/сети/дисплея.

### Задача G. Расчистить main_window (M1) — ОТЛОЖЕНО
1. Выделить из `ui/main_window.py` оркестрацию воркеров в
   `core/task_controller.py` (создание/отмена/closeEvent-cleanup).
2. Окно оставляет layout, вкладки и связывание сигналов.
3. Без изменения поведения — рефакторинг под защитой smoke-прогона.
- **Приёмка:** main_window ≤ ~700 строк; все сценарии (транскрипция, отмена,
  закрытие во время задачи) работают как раньше.
- **Почему отложено:** `MainWindow` можно инстанцировать headless
  (`QT_QPA_PLATFORM=offscreen`), но критерии приёмки требуют проверки живых
  пользовательских сценариев — реальная транскрипция, drag&drop файла,
  отмена в момент закрытия окна — которые нельзя выполнить кликами без
  интерактивного дисплея. Рефакторинг центрального GUI-файла вслепую
  создаёт риск тихо сломать рабочий функционал сильнее, чем оправдывает
  выгода от уменьшения размера файла. Следующему агенту: делать эту задачу
  только с доступом к интерактивному дисплею для ручной проверки.

### Задача H. Консолидация AI-настроек (M5) — ОТЛОЖЕНО
1. Объединить `lm_studio_url`/`book_lm_url` в единый блок настроек LM
   c возможностью переопределения на пайплайн (с миграцией старого конфига —
   `Config.load()` уже умеет игнорировать/маппить поля).
- **Приёмка:** старый config.json загружается без потери значений.
- **Почему отложено:** при повторном рассмотрении `book_lm_url` — не
  дублирование, а осознанная параметризация (книжный пайплайн может
  использовать другую LM Studio модель/инстанс, отдельно от основной AI-панели
  и чата). Объединение потребовало бы правок `ui/settings_dialog.py`
  (GUI, требует интерактивной проверки) ради устранения риска, который пока
  не материализовался. Оставлено как есть; вернуться к этому, если появится
  третий независимый пайплайн и дублирование действительно станет проблемой.

### Задача I. Мелочи (L1–L4) — ВЫПОЛНЕНО частично
- ✅ mypy в CI в режиме `--ignore-missing-imports` по `core/` и движкам
  (информационный шаг, `continue-on-error: true` — кодовая база не типизирована
  полностью, гейтить рано).
- ✅ Windows-заметка в README и ROADMAP: заявка о поддержке Windows не
  соответствовала действительности (нет setup/run-скриптов, CI не проверяет
  эту платформу) — исправлено на честное описание.
- ⏭️ Разнести `engines/` и `scripts/` — не сделано: требует обновления
  импортов по всему UI-слою (`ui/main_window.py` и другие импортируют движки
  из корня напрямую), что относится к той же категории риска, что и задача G.

## 5. Как проверять (обязательный минимум для каждого PR)

```bash
cd Whispered
ruff check .                        # 0 ошибок (после задачи A)
python -m compileall -q .
python -m pytest tests/ -q          # все зелёные, без GPU/сети/дисплея
python main.py                      # smoke, где есть дисплей
```

Правила из `ROADMAP.md` §1.2 (офлайн-first, неблокирующий UI, отмена,
Config-only настройки, один коммит на задачу) — обязательны.
