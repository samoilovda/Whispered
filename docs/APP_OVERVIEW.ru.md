# Whispered — подробное описание приложения

*Составлено 16 июля 2026 по фактическому состоянию кода в этом
репозитории (агент Claude, по запросу владельца). Каждое утверждение
здесь проверено чтением кода или прогоном команд — не пересказ README.*

> Это датированный снимок до редизайна workspace. Актуальные возможности и
> support matrix находятся в `README.ru.md`, текущие приоритеты — в
> `ROADMAP.md`; цифры тестов и описание UI ниже намеренно не обновляются.

Назначение документа: дать читателю (в т.ч. самому владельцу спустя
время) целостную картину — что делает приложение, для кого, насколько
качественно оно сделано и какие технические решения за этим стоят.
Оценка целесообразности дальнейшей разработки — отдельный документ,
[DECISION_2026-07.ru.md](DECISION_2026-07.ru.md).

---

## 1. Что это такое, одним абзацем

Whispered превращает длинную аудио- или видеозапись (интервью, подкаст,
лекция) в готовый к публикации контент: транскрипт с таймкодами и
спикерами, YouTube-пакет (заголовки, описание, главы, теги), статьи в
нескольких форматах, разбор на главы и ключевые моменты, черновик книги.
Вся тяжёлая обработка звука идёт локально (whisper.cpp), а генерация
текста — через локальную LLM (LM Studio) с опциональным облачным
провайдером на своём ключе. Это desktop-приложение на PyQt6, целится в
macOS и Linux, авторства и для использования одним человеком —
владельцем этого репозитория.

Ключевая идея, отличающая его от типового «Whisper GUI»: **транскрипция —
не конечная цель, а первый шаг конвейера, который заканчивается готовым
контентом.**

---

## 2. Для кого и зачем

Судя по содержимому рабочих данных (`input/`, история транскрипций) и
структуре промптов — это инструмент для человека, который:
- ведёт видео/подкаст-интервью на русском (сейчас — и на английском),
- выкладывает их на YouTube и нуждается в заголовках/описании/главах,
- параллельно упаковывает материал в статьи и, иногда, в книгу,
- ценит приватность (аудио не покидает машину) и не хочет платить
  подписку за облачный AI ради рутинной генерации текста.

Это не B2B-продукт и не SaaS — однопользовательский инструмент с
архитектурой, которая, тем не менее, выдерживает публикацию (лицензия
MIT, чистая история коммитов, документация на английском и русском).

## 3. Функциональность — по разделам интерфейса

Приложение организовано как боковая панель (Library / Queue / Recorder) +
рабочая область записи, разделённая на «основной» и «инструментальный»
блок вкладок.

### 3.1 Библиотека (Library)
- История всех транскрипций в SQLite с полнотекстовым поиском (FTS5,
  с fallback на `LIKE`, если FTS-индекс недоступен).
- Карточки записей с бейджами того, какие артефакты уже сгенерированы
  (транскрипт / YouTube-пакет / статья).
- Пресеты запуска одной кнопкой (`launch_bar.py`): «только транскрипция»,
  «YouTube-пакет», «статья», «полный цикл» — цепочка выполняется
  автоматически, результаты сохраняются как отдельные артефакты записи.

### 3.2 Очередь (Queue) и пакетная обработка
- `batch_processor.py`: очередь файлов с статусами, отменяемая, с
  прогрессом по каждому элементу.

### 3.3 Recorder — рабочая область
- Плеер, синхронизированный с транскриптом (клик по слову — перемотка).
- Редактируемый транскрипт с переименованием спикеров.
- Экспорт через меню на 9 форматов: TXT, TXT+таймкоды, SRT, VTT, JSON,
  MD, HTML, DOCX, PDF.
- Разделённые вкладки: «основные» (Transcript, Cleaned) слева и
  «инструментальные» (Articles, Chat, Insights, Cut, YouTube, Book) справа,
  в сплиттере с управляемым соотношением ширины.

### 3.4 Контент-инструменты (уникальная часть продукта)
- **YouTube-пакет** — заголовки, hook+описание, главы с таймкодами
  (гарантированный максимум ~7.5 минут между метками), тайм-коды
  ключевых вопросов, теги. Промпт специально настроен на «зрительские»
  формулировки, а не дословный пересказ.
- **Статьи** — 5 форматов (блог, FAQ, лонгрид-список, саммари, соцпост),
  выбор формата в комбобоксе.
- **Чат с транскриптом** — LLM отвечает на вопросы по содержимому записи,
  контекст обрезается по символьному лимиту (настраиваемо).
- **Инсайты** — главы, action items, ключевые моменты отдельным воркером.
- **Книжный пайплайн** (`book_pipeline.py`, `book_batch_worker.py`) —
  сборка черновика книги из нескольких транскриптов.
- **Cut / EDL** — разметка пауз, экспорт монтажного листа (EDL) для
  видеоредакторов.

Все LLM-задачи используют внешние Markdown-промпты (`prompts/*.md`,
17 файлов) — правка формулировок не требует изменения кода.

### 3.5 Диаризация и запись
- Диаризация спикеров через `pyannote.audio` — тяжёлая зависимость
  подключается лениво (`import` внутри функции), чтобы не тянуть torch
  при обычном запуске.
- Запись с микрофона (`sounddevice`) с выбором устройства и метром
  уровня.

### 3.6 Настройки
- Тема (тёмная/светлая), язык интерфейса (авто/en/ru), кастомный словарь
  для whisper (initial prompt), лимиты контекста для LLM-задач отдельно
  для чата и инсайтов, выбор AI-провайдера (LM Studio / OpenAI / Anthropic
  по BYOK-ключу) — отдельно для YouTube-пакета.

## 4. Архитектура — как это устроено внутри

```
main.py            — точка входа: QApplication, тема, локаль, frozen-runtime setup
ui/          8506   — виджеты PyQt6; main_window.py — оркестратор пресетов
core/        1962   — воркеры (QThread), LLM-клиенты, история, i18n, логи
transcriber.py и    — движки: whisper.cpp в дочернем процессе,
диаризация, экспорт,   диаризация, конвертация форматов, экспорт
видео (root, 4773)
prompts/*.md  257   — 17 промптов, редактируемых без пересборки
tests/       2722   — 292 теста на заглушках PyQt6
```

**Ключевое архитектурное решение: транскрипция — в отдельном процессе,
не потоке.** whisper.cpp гоняется в `multiprocessing`-дочернем процессе
(`transcriber.py`), что даёт **настоящую отмену** (kill процесса) вместо
кооперативной отмены потока, которая для C-расширений вроде whisper.cpp
попросту не работает. Это осознанный выбор, а не случайность — в коде
явно объясняется, почему.

**Все LLM-задачи — в `QThread`-воркерах с общим базовым классом**
(`core/base_worker.py`), общаются с UI через Qt-сигналы. Правило
«ничего дольше ~100мс не блокирует UI-поток» соблюдается системно, а
не от случая к случаю — это зафиксировано как обязательное правило в
`CLAUDE.md`.

**Данные о результате транскрипции — это `Segment(start, end, text,
speaker)`.** Это единственный контракт, который видит вся остальная
система: главы, экспорт, статьи, чат. Движок транскрипции (сейчас —
только whisper.cpp) заменим именно потому, что эта граница узкая и
чистая — проверено на практике 16.07.26 при разведке альтернативных
движков (Parakeet/GigaAM): единственная точка, которую пришлось бы
менять — один `import` внутри дочернего процесса.

**Standalone-сборка (`build.py`) сознательно выносит тяжёлый нативный
стек за пределы `.app`.** whisper.cpp/pywhispercpp и его зависимости
разворачиваются не в бандл (121 МБ), а во внешнюю папку
(`~/Library/Application Support/Whispered/lib`) — так нативную
Metal-сборку можно обновлять отдельно от приложения. Компромисс: это
усложняет `main.py` (`_setup_frozen_runtime`) и требует ручной проверки
перехвата спавн-детей при каждой сборке — но экономит вес бандла и
развязывает жизненный цикл нативной библиотеки от жизненного цикла
приложения.

## 5. Признаки качества разработки — цифрами

| Сигнал | Значение | Комментарий |
|---|---|---|
| Продакшн-код | ~15 200 строк, 84 файла | |
| Тесты | 292, ~2 700 строк, 19 test-файлов | На заглушках PyQt6, не на реальном Qt |
| CI | GitHub Actions, Python 3.10 и 3.12 | ruff + compileall + pytest+coverage на каждый push/PR |
| Линт | ruff, гейт блокирующий | Пре-коммит и CI совпадают — нет дрейфа локали от CI |
| Типизация | ~306 аннотаций, mypy в CI | **Информационно, не блокирует** — codebase не полностью типизирован |
| Докстринги | ~340 | На нетривиальных функциях, не карго-культ |
| История коммитов | 90 коммитов, с 14.01 по 16.07.26 | Один шаг — один коммит, конвенция `feat/fix/docs/chore` соблюдается |
| Лицензия | MIT | |
| Документация | README (en+ru), ROADMAP, CLAUDE.md, STRATEGY, PERSPECTIVES | Публично-презентабельный уровень |

**Что тесты покрывают, а что — нет:** юнит-тестами закрыты чистая логика
(`config`, `exporters`, `history`, `i18n`, `llm_text`, `text_processor`,
`timeline_export`, `utils`, LLM-клиенты). **Не покрыты тестами**:
`transcriber.py`, `diarizer.py`, `video_cut.py`, `video_input.py`,
`book_pipeline.py`, `main.py`, `build.py` — то есть именно движковый и
инфраструктурный слой, где баги дороже всего. Это компенсируется
headless real-Qt смоуком (`QT_QPA_PLATFORM=offscreen`) в пре-коммит
гейте, но смоук — не то же самое, что автоматизированный тест: он ловит
«приложение не падает при старте», а не «сплиттер держит нужное
соотношение» — именно такую регрессию тесты пропустили 16.07.26 (см.
ниже).

**Честная иллюстрация зрелости процесса**, а не гипотеза: 16 июля внешний
участник (Gemini) внёс UI-правки. Все 292 теста прошли зелёными. Но при
ручной визуальной проверке нашлись две реальные регрессии, которые
тесты структурно не могли поймать: `QSplitter` держал пропорцию 1:2
вместо заявленных 2:1 (стартовые размеры берутся из `sizeHint`, а не из
`setStretchFactor`, как предполагал автор правки), и комбобокс обрезал
текст после того, как увеличили размер шрифта темы. Это не провал
процесса — наоборот, признак того, что у проекта есть привычка проверять
глазами то, что тесты в принципе не могут проверить, — но это же и
показывает объективный предел текущего гейта: **UI-корректность
поведения (не крэш, а именно "выглядит и ведёт себя правильно") держится
на ручной проверке, а не на автоматике.**

## 6. Технические решения, которые стоит знать читающему код впервые

- **Локальная LLM по умолчанию, облако — опция на своём ключе.**
  Осознанное архитектурное ограничение, а не недоделка: `CLAUDE.md`
  фиксирует это как обязательное правило («offline first»).
- **Промпты вынесены в Markdown, а не зашиты в код** — изменение
  формулировок не требует деплоя, это по сути config-as-content.
- **Диаризация и тяжёлые ML-зависимости импортируются лениво** —
  `pyannote.audio`/`torch` не тянутся при обычном запуске без диаризации.
- **`word_timestamps=True` в whisper отключён по умолчанию** — известный
  баг склеивания кириллических слов в группировке сегментов (см. код и
  комментарии в `transcriber.py`); включать только зная об ограничении.
- **LM Studio как единственный локальный бэкенд** — привязка к
  конкретному инструменту, а не к протоколу; хотя формально используется
  OpenAI-совместимый API, так что смена на другой локальный сервер
  технически дёшева.
- **Один прогон = один процесс для транскрипции, но потоки — для LLM.**
  Разные модели конкурентности для разных типов работы, выбранные
  осознанно под характер задачи (жёсткая отмена C-расширения vs.
  сетевой I/O).

## 7. Известные ограничения (не полировка, а факты)

- Диаризация — как и у конкурентов — не идеальна: может делить одного
  спикера на несколько (то же ограничение, что и в проприетарных
  продуктах на этом рынке).
- Движок транскрипции — только whisper.cpp; разведка альтернатив
  (Parakeet, GigaAM через `onnx-asr`) на 16.07.26 показала, что архитектура
  готова к добавлению движков, но интеграция ещё не сделана.
- LM Studio при параллельных запросах на длинных транскриптах может
  перестать отвечать, оставаясь в статусе "running" — задокументированный
  готча, обходится последовательным запуском воркеров.
- Стандалон-сборка проверена и работает на macOS; Linux — через
  AppImage-скрипт, но менее обкатан на реальных релизах; Windows —
  не поддерживается.
- Тестовый гейт не покрывает движковый слой и UI-поведение (см. §5).
