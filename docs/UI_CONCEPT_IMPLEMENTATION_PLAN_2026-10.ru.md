## 0. Правила, которые этот план не отменяет

Пять инвариантов Трека B действуют для каждой фазы. Самые частые способы их
нарушить именно в этом плане:

1. **У генерации ровно один вход** (инвариант 4). Не добавлять кнопок
   «Сгенерировать», «↻ секцию», «В рецепт ▸» в просмотрщики. Перезапуск шага
   — только экран прогона (`ui/run_view.py`) и `Ctrl+K` («Restart: …»).
2. **Две колонки** (B6): Библиотека | центр. Никаких правых панелей на
   экране записи.
3. **Вариант 2 («документ и его материалы») отклонён.** Не вводить хаб
   «Материалы» со списком — вкладки записи остаются просмотрщиками шагов.
4. **Ничего не обрезается** (инвариант 5): каждый новый текстовый виджет
   проходит `tools/render_ui_gallery.py --check`.
5. **Статус не только цветом** (WCAG 1.4.1): глиф + текст.

Плюс правила `CLAUDE.md`: офлайн, UI не блокируется, одна фаза = один
коммит, гейт зелёный после каждой фазы, `word_timestamps=True` не включать
(ломает кириллицу).

**Известный посторонний сбой.** На `main` (до этого плана) падают 4 теста
`tests_qt/test_recipe_retry.py` — `runner.wait(5000)` возвращает `False`.
Не чинить «заодно» и не считать регрессией своей фазы; сравнивать с
`git stash`-прогоном.

## Y — вкладка YouTube

### Что было (диагноз)

- `ui/youtube_panel.py`: пять секций в `QToolBox`, все `QPlainTextEdit`
  только для чтения.
- `core/youtube_description.py::format_youtube_description` молча
  выбрасывал главы ближе 10 с, молча ставил первую на 0:00, а при < 3 главах
  только писал в лог — YouTube такие главы не покажет вовсе.

  остаток невыполненной части B5.

  (`insights.json` → `chapters`) — две независимые генерации одного типа
  insight; `InsightsCache` склеивает их только внутри сессии.
- Результат шага лежит в `<artifact_dir>/youtube_package.json`
  (`application/steps.py::_youtube_package_runner`), манифест провенанса —
  рядом.

### Y2. Доводка B5: панель без своего запуска

**Решение владельца (2026-10-07):** запуск одного шага `youtube_package`
для открытой записи **нужен** — в том числе для записи, сделанной другим
рецептом. Это единственный вход в генерацию YouTube-пакета вне рецепта.

**Что выяснилось при разборе кода.** Комбобоксы панели — не параметры
шага, а замаскированные глобальные настройки: провайдер пишется в
`Config.yt_provider`, и его же читают **все** LLM-шаги рецептов
(`provider_from_config(cfg)` в `ui/main_window.py`), а язык из панели
действовал только на одиночный запуск — рецепт всегда брал язык записи.
Поэтому их место — Настройки, а не рецепт.

**Y2a.** `feat: run the YouTube package step alone from the menu and Ctrl+K`
— пункт меню «Файл → Создать YouTube-пакет» (попадает в `Ctrl+K`
автоматически через таблицу `_init_menu_bar`), слот открывает запись,
вкладку YouTube и зовёт `_start_youtube_job()`; без открытой записи —
тост; повторный запуск, пока идёт текущий, игнорируется.

**Y2b.** `refactor: move YouTube provider and language to Settings; the
panel becomes a step viewer`:

1. `Config.yt_language: str = ""` (`""` — язык записи, иначе имя языка
   для промпта: `"Russian"`, `"English"`). Шаг `youtube_package` читает
   `params["yt_language"]` и только при пустом значении —
   `params["language"]`, поэтому настройка действует и на рецепт, и на
   одиночный запуск, но не трогает язык остальных шагов.
2. Вкладка «ИИ» Настроек: провайдер (`yt_provider`), «Настроить…»
   (`ProviderDialog`), предупреждение об отправке текста в облако (видно
   только для облачного провайдера), язык YouTube-материалов.
3. Из панели убрать `_lang_combo`, `_provider_combo`, `_configure_btn`,
   `_privacy_notice`, `_gen_btn`, `_retry_bar`. Вместо них одна ссылка
   `_run_link`, видимая, когда пакета нет или шаг упал: «Создать
   YouTube-пакет» / «Повторить». Она эмитит тот же `generate_requested`,
   что и пункт меню, — второго пути запуска нет.
4. `publish_texts()["language"]` берёт код из `Config.yt_language`, иначе
   язык записи — контракт публикации не меняется.

**Найдено по ходу и исправлено** (`fix:`, отдельный коммит): язык не
входил в ключ кэша артефакта `youtube_package`, поэтому смена языка и
повторный запуск отдавали старый пакет из кэша. Язык теперь входит в
`prompt_version` шага.

**Приёмка.** В `YouTubePanel` нет ни одного `QComboBox`; провайдер и язык
меняются в Настройках и действуют на следующий запуск;
`test_youtube_step_wiring.py` и `test_youtube_publish_texts.py` зелёные;
облачный провайдер по умолчанию выключен (`yt_provider = "lmstudio"`,
правило 1 `CLAUDE.md`).

### Y3. Правки глав пользователем — СДЕЛАНО

**Коммиты.** `d7ba23a feat: user-edit overlay kept beside a step's result`,
`f525681 feat: edit YouTube chapters by hand`.

1. Правки хранятся **отдельно** от результата шага:
   `<artifact_dir>/youtube_package.user.json`, только изменённые ключи.
   Сейчас ключ один — `chapters`; Y4/Y5 добавят свои (`title_index`,
   `tags`, `offset`) в тот же файл. `youtube_package.json` и его манифест
   панель не трогает — кэш шага не принимает правку за вывод модели.
2. `application/user_edits.py` (Qt-free, атомарная запись как в
   `artifact_store`): `overlay_path`, `load_overlay` (битый файл = нет
   правок), `save_overlay` (пустой оверлей удаляет файл), `set_edit` /
   `drop_edit` / `rebase_edit` / `is_stale`. У каждого ключа `k` рядом
   лежит `k_base` — отпечаток значения модели, против которого сделана
   правка.
3. **Отступление от первоначального плана: вместо таблицы — текстовый
   редактор.** «Изменить главы» превращает раздел в редактор строк
   «М:СС Название» — ровно тот формат, который читает YouTube. Видны все
   главы со своим временем, включая те, что YouTube отбросил бы, — их
   можно исправить. Отдельная кнопка «Объединить с предыдущей» не нужна:
   это правка строки. «Вставить время плеера» добавляет строку с
   позицией плеера. Неразобранные строки держат редактор открытым и
   перечисляются по номерам. Разбор и обратное форматирование —
   `parse_chapter_lines` / `format_chapter_lines` /
   `parse_timestamp` в `core/youtube_description.py`.
4. **Отступление: без модального диалога в экране прогона.** Правка
   побеждает везде, где используются главы (строки, проверки Y0,
   Копировать/Сохранить, тайм-коды в описании, диалог публикации). Если
   перезапуск дал те же главы — правка молча остаётся. Если главы модели
   изменились (`is_stale`), в разделе появляется заметка «Модель
   пересоздала главы после ваших правок — показаны ваши» и две кнопки:
   «Взять главы модели» / «Оставить мои». Ни одна сторона не теряется
   без явного выбора, и это работает одинаково для прогона рецепта и
   одиночного запуска.
5. `publish_texts()` отдаёт описание с отредактированными тайм-кодами и
   проверку отредактированных глав.

**Ограничение, которое осталось.** Запись, открытая из Библиотеки, не
восстанавливает YouTube-пакет с диска (так было и до Y3): он появляется во
вкладке после прогона рецепта или одиночного запуска, и тогда же
подхватывается оверлей. Одиночный запуск на неизменённом транскрипте
берётся из кэша и происходит мгновенно.

### Y4. Описание целиком: блоки, счётчики, название, теги — СДЕЛАНО

**Коммиты.** `6ef7d91 fix: YouTube key questions keep their own times`,
`63e15c8 feat: build the YouTube description from blocks`,
`0fa6a18 feat: pick the YouTube title and see title and tag limits`.

1. `compose_description(blocks=…)` в `core/youtube_description.py`:

2. `Config.yt_channel_signature` + многострочное поле во вкладке «ИИ»

7. **Найдено и исправлено отдельно:** ключевые вопросы форматировались

   вопросы пропадали; в описании такой список мог быть принят YouTube за
   главы. Теперь у вопросов их собственное время.

которой нет в записи. `check_chapters` получает `offset` параметром, чтобы
проверки считались по тем временам, которые увидит YouTube.

**Коммит.** `feat: shift YouTube timecodes for an intro the recording lacks`

### R3. Закладки

### R4. Меню выделения в транскрипте

Для выделения в `ui/transcript_view.py`: «Копировать с таймкодом»,
«Закладка», «Глава отсюда» (пишет в оверлей Y3), «Вырезать» (см. R5).
Никакого «запустить рецепт на фрагменте».

### R5. Вырезанное зачёркиванием (Descript «Ignore»)

Сейчас Монтаж — список сегментов с галочками (`ui/cut_view.py`). Пометка
«вырезать» из транскрипта ставит ту же отметку, что и галочка в Монтаже, и
в транскрипте сегмент показывается зачёркнутым; снятие — по клику.
**Гранулярность — сегмент, не слово:** словесные тайм-коды требуют
`word_timestamps=True`, а он ломает кириллицу. Не обходить это.

### R6. Неуверенные фрагменты

1. `transcriber.py`: передать `extract_probability=True` в
   `model.transcribe(...)` (параметр есть в `pywhispercpp`, отдаёт
   `segment.probability` — геометрическое среднее вероятностей токенов,
   NaN если не посчитано).
2. `domain/transcription.py::Segment`: поле `confidence: float | None =
   None`. Сериализация: `core/history.py::_result_to_payload` и
   `ui/main_window.py::_result_from_payload` — старые записи без поля
   читаются как `None`.
3. Подсветка сегментов ниже порога (порог — константа, подобрать на
   реальных файлах из `input/`, ru и en) пунктирным подчёркиванием, счётчик
   и переход «следующий неуверенный».
4. Сначала замерить на реальном файле, что `extract_probability` не
   замедляет расшифровку заметно и не меняет текст.

**Приёмка R6.** Старая БД открывается; запись без `confidence` ничего не
подсвечивает; mypy-блокирующий набор чистый (`transcriber.py`, `domain/`).

У каждой строки Итогов с `start` — ссылка «↗ таймкод» (для глав и ключевых
моментов уже есть; добавить задачам, если модель возвращает время; если нет
— не выдумывать время на клиенте).

### I3. Своё и сгенерированное (после L1)

Когда появятся заметки пользователя (L1), текст пользователя показывается
основным цветом, добавленный моделью — приглушённым. До L1 не делать:
сейчас весь текст Итогов сгенерирован, различать нечего.

## S — стартовый экран

### S1. Готовность рецепта одной строкой

Под переключателем рецептов в `ui/start_view.py` — строка готовности
**выбранного** рецепта: модель Whisper скачана, ffmpeg, LM Studio отвечает
и модель загружена (`lm_studio_manager.py::is_server_running` и уже
существующий пробник статус-бара — не делать второй), модель спикеров
(`diarizer.py::is_available`) — только если в рецепте есть `diarize`. Каждый
непройденный пункт — со ссылкой на исправление. Проверки асинхронные
(правило 2), результат кэшируется на сессию. Правую колонку не добавлять.

## L — Живая запись

### L1. Заметки во время сессии

Поле «Мои заметки» рядом с живым транскриптом; `⌘↵` вставляет метку
времени. Заметки сохраняются вместе с записью и передаются шагу `insights`
как дополнительный вход (новый плейсхолдер в `prompts/` для заметок; без
заметок промпт ведёт себя как сейчас). Рецепт в шапке «Живой» —
только для чтения.

**Границы.** `Config.live_transcription_enabled` и Gate A/B из
`docs/LIVE_TRANSCRIPTION_PLAN.ru.md` не трогать. Это новая функция, а не
расширение готовности Live.

## T — меню в строке состояния (последним, по отдельному решению)

`QSystemTrayIcon` с действиями: диктофон, живая встреча, открыть файл,
недавние записи, текущая обработка. **Не вторая очередь:** меню только
зеркалит модель статус-бара. Глобальные горячие клавиши и напоминание о
начале встречи — отдельные решения со своими платформенными ограничениями
(macOS — основная платформа, Linux/Windows — preview); в этот план не
входят.
