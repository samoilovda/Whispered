## P1. `ui/main_window.py` — god-object

**Факты:** 1723 строки, 82 метода, 64 атрибута экземпляра, 68 вызовов
`.connect()`, 40 импортов, **0 % покрытия**. `_setup_ui()` — 232 строки.

Класс одновременно оркестрирует: транскрипцию, live-сессию, preset-цепочку,
AI-цепочку (clean → article → generate all), экспорт, EDL, video draft,
book-pipeline и историю. Плюс два worker-класса объявлены прямо в файле
(`GPUDetectionWorker`, `DraftAssemblyWorker`).

`closeEvent` (50 строк) — ручная лестница из 15 `hasattr`-проверок, местами
лезущая в приватные члены чужих виджетов:

```python
if hasattr(self, 'book_panel') and self.book_panel._batch_worker:
    self.book_panel._cancel_batch()
```

**Предложение**

1. Ввести протокол `Shutdownable` (`cancel()` / `cleanup()`); панели
   регистрируются в `self._shutdownables`, `closeEvent` просто итерирует.
   Убирает и `hasattr`-лестницу, и обращения к приватным членам.
2. Вынести контроллеры (обычные `QObject`, без виджетов — значит,
   тестируемые под застабанным Qt):
   - `ui/controllers/transcription_controller.py` — `_start_transcription`,
     `_on_progress`, `_on_finished`, `_on_error`, `_reset_ui`
   - `ui/controllers/preset_chain.py` — 4 поля состояния
     (`_chain_pending`, `_chain_ran`, `_chain_had_error`,
     `_chain_auto_article`) + `_start_preset_chain` … `_finish_preset_chain`.
     Это конечный автомат, размазанный по классу; в отдельном модуле его
     можно покрыть тестами полностью
   - `ui/controllers/live_controller.py` — 12 `_live_*`/`_on_live_*` методов
   - `ui/controllers/ai_chain_controller.py` — clean/article/generate-all
3. `_setup_ui` разбить по секциям (`_build_library_section()`,
   `_build_record_section()`, …).

Цель: `MainWindow` ≤ 400 строк — композиция и роутинг, без бизнес-логики.

## P2. `core/__init__.py` протаскивает PyQt6 во всё

```python
# core/__init__.py — «Business logic and infrastructure, independent of UI layer»
from core.ai_worker import AIProcessingWorker   # → PyQt6.QtCore
```

Проверено: `import core.paths` загружает `PyQt6.QtCore`. То есть пакет,
который в собственном докстринге объявлен независимым от UI, тащит Qt в любой
headless-сценарий (дочерний процесс транскрипции, CLI-скрипты, быстрые тесты).

Реэкспорты при этом **никем не используются** — единственные `from core import …`
в репозитории импортируют подмодули (`platform_support`, `external_tools`),
а не эти пять символов.

**Предложение:** удалить тело `core/__init__.py` (оставить докстринг). Стоимость
— нулевая, эффект — восстановленная граница слоёв. Заодно это приводит `core/`
в соответствие с правилом из CLAUDE.md, уже действующим для `ui/__init__.py`.

Отдельно: `core/live/__init__.py` — 121 строка жадных реэкспортов всех 19
подмодулей; любой `from core.live.contracts import SegmentUpdate` тянет
`sounddevice`, `system_audio_source` и прочее. Сузить до типов из `contracts`
либо убрать так же.

## P3. Дублирование worker-ов: 17 классов, `BaseWorker` использует 3

`core/base_worker.py` даёт ровно то, что нужно (thread-safe отмена + перехват
исключений в `run()`), но унаследованы от него только `ChatWorker`,
`InsightsWorker`, `AIProcessingWorker`. Остальные 14 переписывают
`threading.Event` + `try/except` вручную:

`GPUDetectionWorker`, `DraftAssemblyWorker` (main_window), `LMStudioTaskWorker`
(ai_panel), `ConnectionChecker` (book_panel), `_ConnectionChecker`
(settings_dialog), `TargetDiscoveryWorker`, `LivePreflightWorker`,
`DownloadWorker`, `DiarizationCacheWorker`, `BatchWorker`,
`TranscriptionWorker`, `BookBatchWorker`, `PersistentWhisperWorker`.

Хуже того — **три независимые проверки соединения с LM Studio**, и одна из них
переписывает HTTP с нуля мимо `core/lm_client.py`:

```python
# ui/settings_dialog.py:33 — дублирует LMStudioClient.check_connection()/get_loaded_model()
with urllib.request.urlopen(req, timeout=5) as resp:   # без auth-заголовков,
    data = json.loads(resp.read())                     # без сериализующего локa
```

**Предложение**

1. Один `core/lm_status_worker.py` на базе `BaseWorker`, поверх
   `LMStudioClient`; выпилить `_ConnectionChecker` и `ConnectionChecker`,
   свести к нему ветку `"status"` из `LMStudioTaskWorker`.
2. Перевести остальные worker-ы на `BaseWorker` (механическая правка,
   ~10 строк минус на класс).
3. Заодно закрывается риск расхождения: сейчас правка таймаутов или
   auth-заголовков в `lm_client.py` не доезжает до диалога настроек.

**Предложение** (поэтапно, по одному коммиту на группу, с временными

## P6. `core/history.py` — миграции без версии схемы

`PRAGMA user_version` не используется; вместо этого два ad-hoc метода
`_migrate_artifacts_column()` и `_migrate_source_kind_column()`, каждый —
`try: ALTER TABLE / except: pass`. Каждая новая колонка = ещё один такой метод;
порядок и идемпотентность держатся на честном слове.

**Предложение:** список миграций + `PRAGMA user_version`:

```python
_MIGRATIONS = [_v1_initial, _v2_artifacts, _v3_source_kind]
# применить всё, что выше текущего user_version, затем выставить len(_MIGRATIONS)
```

Тестируется на временной БД; даунгрейд-детект появляется бесплатно.

## P7. mypy: реальные баги под `continue-on-error`

Сейчас: 28 ошибок в `core/` + перечисленных корневых модулях, **62 ошибки
в `ui/`** — и `ui/` в CI вообще не проверяется. Флаг `continue-on-error: true`
означает, что регрессии никто не видит.

Среди находок — не стилистика, а потенциальные падения:

- `core/recorder.py:169: "None" has no attribute "start"`
- `ui/main_window.py:572: Argument "segments" … has incompatible type
  "list[object]"; expected "list[Segment]"`

**Предложение:** починить 28 ошибок в `core/` и снять там `continue-on-error`
(жёсткий гейт), `ui/` добавить в проверку информационно с фиксацией текущего
числа ошибок как потолка.

## P8. 89 широких `except Exception`, 10 из них — молчаливые

Вне тестов: 89 `except Exception`, из них 10 сразу за `pass`. Такие места
превращают сбой в «ничего не произошло» — самый дорогой класс багов в
десктопном приложении, где пользователь не смотрит в лог.

**Предложение:** пройти по 10 «глухим» сайтам; там, где подавление осознанное
(cleanup, best-effort), оставить с `logger.debug("...", exc_info=True)` и
комментарием «почему». Остальные — сузить до конкретных исключений.

## P9. Ключи API в открытом виде

**Предложение** (не срочно, но до публичного релиза Windows): опциональный
бэкенд `keyring` с фолбэком на текущий файл. На macOS это Keychain «бесплатно»,
на Windows — Credential Manager.
