Изображения получены из реальных Qt-виджетов в Linux с `QT_QPA_PLATFORM=offscreen`. Это не макеты. Данные и результаты прогона синтетические; генерация LLM/ASR и публикация не запускались. Gallery специально включает экспериментальный Live для покрытия его экранов: наличие вкладки на изображении не означает, что она включена по умолчанию. Время в синтетических карточках использует часовую зону executor; дата отчёта — Asia/Tashkent.

## Воспроизводимость

Штатная галерея:

```bash
QT_QPA_PLATFORM=offscreen XDG_DATA_HOME=/tmp/whispered-uiux-gallery-data \
    .venv/bin/python tools/render_ui_gallery.py --check \
    --output /tmp/whispered-uiux-gallery
```

Фактический результат аудита: exit 0, 88 изображений. Сохранены четыре иллюстрации, а не весь автоматически генерируемый набор. Проверка галереи не покрывает всю доступность, не доказывает работу реального аудио и пропускает измеренное вертикальное сжатие.

Адресные пробы выполнялись в отдельной конфигурации/SQLite с подменой LM Studio probe; ключи не использовались. Для повторения предпочтительно написать real-Qt regression tests на существующих fixtures `tests_qt/conftest.py`:

1. **Геометрия:** открыть start, RU/dark, 1100×700, дождаться обработки Qt events; сравнить `height()`/`sizeHint().height()` у `file_selector.browse_btn`, прочитать геометрию детей drop-zone и снять изображение. Измеренное 23/34 px относится к кнопке, а 157/212 — к контейнеру.
2. **Readiness:** вызвать `recipe_checks(['transcribe', 'insights'], ['insights'], ReadinessFacts('fixture', True, True, llm_provider='openai', llm_reachable=False, cloud_key_set=True))`. Наблюдался `ready_cloud_ok` для локального шага.
3. **Drop:** дать одинаковый QMimeData с двумя локальными `.wav` путями `FileSelector.dropEvent()` и `MainWindow._collect_dropped_paths()`. Первая ветка передаёт один путь, вторая возвращает два. Это проверка обработчиков; нативный drag-and-drop на ОС отдельно не проверялся.
4. **Библиотека:** создать 205 записей через `HistoryStore.add`, вызвать `LibraryView.refresh`; в `_records` 200, старейшей записи нет. Физически записи из БД не удалены.
5. **Правка:** A → `_enter_edit_mode()` → изменить `text_edit` → открыть B → A. Измерить буфер и сохранённый payload A: новая фраза потеряна.
6. **Монтаж:** A → `cut_view.set_cut([1], True)` → B → A. Список `[1]` сброшен до `[]`.
7. **Чат:** записать два синтетических сообщения в conversation A → B с другим текстом → A. В памяти ноль сообщений. Отдельная проверка `set_transcript()` с одинаковым текстом сохраняет старую историю, поэтому нужна идентичность record.
8. **Контраст:** относительная яркость sRGB, формула `(Lmax + 0.05) / (Lmin + 0.05)`. В JSON — пары семантических цветов из `ui/theme.py`; они не являются полным анализом всех отрисованных пикселей и состояний.

Для конкурентов прочитаны закреплённые README и просмотрены официальные изображения Buzz/Vibe/noScribe. Сами приложения не запускались; SHA256 позволяет проверить неизменность источника. Изображения конкурентов не копировались в репозиторий. Внешние источники подтверждают заявленные возможности, но не измеренную производительность, качество ASR или удобство полного сценария.
