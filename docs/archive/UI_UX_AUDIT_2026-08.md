## P0 — сломанное поведение

### 1. Кнопка разворота сайдбара не работает при размере окна по умолчанию

`ui/main_window.py:823-833` (`resizeEvent`), `ui/main_window.py:252-253`.

Окно по умолчанию — 1100×700, минимум — 900×550. Порог авто-сворачивания —
`width < 1180`. То есть **из коробки сайдбар всегда свёрнут в 64px рельс без
подписей**, а нажатие кнопки разворота отменяется первым же событием resize.

Проверено программно:

```
user expanded          -> expanded 200
after real resize      -> COLLAPSED (выбор пользователя потерян) 64
config.sidebar_collapsed = False   (UI и конфиг разошлись)
```

Пользователь видит: кнопка «‹» нажимается, панель разворачивается и тут же
схлопывается обратно. Настройка при этом сохраняется в конфиг как «развёрнут»,
и при следующем запуске на широком мониторе поведение внезапно другое.

**Как чинить.** Разделить два разных понятия, которые сейчас склеены в одном
булеве: явный выбор пользователя (`cfg.sidebar_collapsed`) и вынужденное
сжатие по нехватке ширины. Резолвить как «свёрнут, если пользователь так
выбрал ИЛИ окна физически не хватает», но **не перезаписывать выбор
пользователя**, и не сохранять в конфиг то, что вызвано resize. Порог 1180
опустить ниже дефолтного размера окна (сайдбар 200px + рабочая область ~700px
помещаются в 900), иначе развёрнутое состояние недостижимо на дефолте.
`Sidebar.set_collapsed` уже принимает `emit=False` — этого мало, нужен
отдельный флаг «сжато принудительно».

### 2. На вкладке «Очередь» одновременно два пустых состояния

`ui/batch_panel.py:118` (конец `__init__`), `147-159`, `229-230`.

`_refresh_list()` — единственное место, где выставляется видимость
`file_list` / `empty_state` — не вызывается при конструировании. На холодном
старте видны **оба**: пустая рамка списка высотой 264px и под ней настоящий
пустой стейт.

```
processor item count: 0
file_list visible: True   empty_state visible: True
file_list height: 264
after _refresh_list() -> file_list visible: False
```

**Как чинить.** Вызвать `self._refresh_list()` в конце `BatchPanel.__init__`.
Так же, как `MainWindow.__init__` уже делает `self.library_view.refresh()`
для той же самой проблемы на Библиотеке (`ui/main_window.py:204`) — это
известный в проекте паттерн, просто пропущенный здесь.

### 3. Кнопки в правой панели экрана записи обрезаны посреди слова

`ui/record_view.py:173-182`.

`self._content_splitter.setSizes([900, preferred_tools])` — жёстко зашитые
900px на левую панель, тогда как вся рабочая область при окне 1100px это
~1035px. Правая панель схлопывается, и её содержимое режется:

- `Копирова` (вместо «Копировать»)
- `Экспорт .r`, `Экспорт .h` (вместо «Экспорт .md» / «Экспорт .html»)
- ряд чипов `Блог / FAQ / Список` уезжает под стрелки прокрутки
- заголовок «Инструменты» сталкивается с комбобоксом «Статьи»
- кнопка «Экспорт» левой панели обрезана границей сплиттера

**Обрезка сохраняется и при 1440×900** — то есть это не только про узкие окна.

**Как чинить.** Задавать размеры сплиттера от фактической ширины
(доля, а не абсолютные 900), пересчитывать в `showEvent`/`resizeEvent`, а не
один раз в `set_content_widgets`. Кнопкам экспорта дать перенос или
`QFontMetrics.elidedText`, чтобы вместо `Экспорт .h` было читаемое
многоточие. Лучше — заменить три кнопки экспорта на одно меню, как уже
сделано в шапке (`_build_export_menu`).

### 4. Строка параметров в Launch bar обрезается посреди слова

`ui/launch_bar.py:77-81`.

`summary_label` — обычный `QLabel` без elide и без ограничения ширины:

```
sizeHint width: 473px   actual width: 353px
```

Пользователь видит `… · ⚡ Ба` — обрывок. При 900px хуже: `самая компактная и б`.

**Как чинить.** Elide по `QFontMetrics.elidedText` в `resizeEvent`, полный
текст — в tooltip. `setMinimumWidth(0)` + `setSizePolicy(Ignored, Preferred)`,
чтобы метка не распирала строку.

### 5. Пустое состояние наезжает само на себя при 900×550

`ui/empty_state.py` — фиксированный вертикальный стек
(иконка 48px + 16 + заголовок + 4 + подсказка + 12 + кнопка) без
минимальной высоты и без компактного режима.

При 900×550 (близко к минимальному размеру окна): иконка визуально ложится
на заголовок «Пока нет записей», вторая строка подсказки —
«нажмите «Выбрать файл» выше.» — обрезана целиком.

**Как чинить.** Компактный режим по аналогии с
`FileSelector.set_compact()` (уже вызывается из `resizeEvent` при height < 650,
`ui/main_window.py:825-826`): уменьшать иконку до 32px и прятать подсказку,
когда доступная высота мала.

### 6. Скроллбар перекрывает кнопки запуска на экране «Эфир»

`ui/live_view.py:53-61` (`QScrollArea`), `72-76`, `98-106`.

Кнопки «Старт», «Пауза», «Стоп» упираются в правый край и перекрываются
вертикальным скроллбаром — главное действие экрана физически подрезано.

**Как чинить.** Зарезервировать ширину скроллбара
(`scroll.setViewportMargins` или `verticalScrollBar()->sizeHint().width()`),
либо вынести ряд действий из области прокрутки в закреплённый низ экрана —
он и логически не должен уезжать вместе с формой.

## P1 — доступность и понятность

### 7. Состояние чекбокса передаётся только цветом

`ui/theme.py:406-419`. `::indicator:checked` меняет только `background-color`
на акцент — глифа «галочка» нет. Отличие «включено/выключено» — исключительно
заливка 14×14px. Это нарушение WCAG 1.4.1 (Use of Color) и просто плохо
читается: на экране «Эфир» чекбоксы «Микрофон» / «Звук встречи» выглядят как
цветные квадратики-образцы, а не как переключатели.

**Как чинить.** Добавить `image:` с SVG-галочкой в `::indicator:checked`
(в `ui/icons.py` уже есть набор иконок, есть `check`).

### 8. Активный фильтр в Библиотеке неотличим от неактивных

`ui/theme.py:737-747`. У `role="quick-chip"` **нет правила `:checked`** —
только базовое и `:hover`. Кнопки при этом `setCheckable(True)` и собраны в
эксклюзивную `QButtonGroup` (`ui/library_view.py:186-198`).

Итог: «Все / Файлы / Диктофон / Эфир» выглядят одинаково, и понять, какой
фильтр применён, невозможно.

**Как чинить.** Добавить `QPushButton[role="quick-chip"]:checked` с заливкой
акцентом и контрастным текстом.

### 9. Светлая тема: контраст ниже порогов WCAG

`ui/theme.py:135-165`. Посчитанные коэффициенты на `bg_base #f0f0f0`:

| Токен | Значение | Контраст | Порог |
|---|---|---|---|
| `text_muted` | `#777777` | **3.93:1** | 4.5:1 (текст) |
| `IconColors.DEFAULT` | `#888888` | **3.11:1** | 4.5:1 / 3:1 |
| `border_input` | `#cccccc` | **1.41:1** | 3:1 |
| `accent` (как текст) | `#6366f1` | **3.92:1** | 4.5:1 |
| `text_secondary` | `#555555` | 6.54:1 | ok |

`border_input` при 1.41:1 — причина того, что зона drag-and-drop в светлой
теме почти не видна. Дополнительно:

- `IconColors` (`ui/theme.py:40-46`) намеренно не зависит от темы — комментарий
  в коде это признаёт, но `#888888` на светлом фоне не проходит.
- `TIMELINE_COLORS` (`ui/theme.py:52-62`) — **захардкоженные тёмные цвета
  независимо от темы**; комментарий в коде честно называет это
  «pre-existing limitation». В светлой теме `ProgressTimeline` рисуется
  тёмными плашками на светлом фоне.

**Как чинить.** Затемнить `text_muted` до ~`#5f5f5f`, `border_input` до
~`#b0b0b0`; сделать `IconColors` и `TIMELINE_COLORS` функциями от активной
темы (обе структуры уже централизованы — менять надо в одном месте).

### 10. Отключённые главные кнопки не объясняют, почему они отключены

«Обработать» (`ui/launch_bar.py:59-66`), «Старт» на Эфире
(`ui/live_view.py:72-76`), «Запустить очередь», «Создать статьи» — стартуют в
`setEnabled(False)` со статическим тултипом, который описывает действие, а не
условие разблокировки. На пустой Библиотеке это главная кнопка экрана, и она
выглядит мёртвой.

**Как чинить.** Динамический tooltip/подпись: «Сначала выберите файл»,
«Сначала выполните проверку готовности». Условие уже вычисляется в местах
вызова `setEnabled` — достаточно рядом класть причину.

## P2 — консистентность и композиция

11. **Дублирование призыва к действию.** На «Очереди» две кнопки «Добавить
    файлы» одновременно — в шапке (`ui/batch_panel.py:139-142`) и в пустом
    стейте (`152-158`). Скрывать вторичную, пока список пуст.

12. **Пустота на экране «Диктофон».** Контент занимает верхние ~240px, ниже
    ~70% страницы пусто. Кандидат — показывать здесь последние записи
    диктофона или свернуть секцию в карточку.

13. **Смешанная иконография.** Текстовые глифы `↺` и `⋯` как иконки
    (`ui/library_view.py:168-181`) при наличии SVG-набора в `ui/icons.py`;
    `↺` к тому же не отрисовывается в системном шрифте. Плюс эмодзи
    (📝 ✨ 📦 ❓ 📋) в подписях вкладок и кнопок вперемешку с SVG-иконками.
    Привести к одному источнику — `get_icon()`.

14. **Дублированный заголовок** на экране записи: вкладка «Транскрипт» и
    прямо под ней заголовок секции «Транскрипт». Убрать второй.

15. **Диалог настроек** (`ui/settings_dialog.py`): у списка категорий
    постоянная синяя рамка, выглядящая как залипший focus ring; на странице
    «Общие» пять контролов и ~400px пустоты; «Применить» в отключённом
    состоянии практически невидима; поиска по настройкам нет.

16. **`_on_section_changed` не синхронизирует рельс.**
    `ui/main_window.py:494-500` переключает `QStackedWidget`, но не вызывает
    `sidebar.set_active(key)`. Сейчас это не видно при кликах (кнопки
    checkable в эксклюзивной группе), но каждый программный переход обязан
    руками звать обе функции — `_goto_section` (`:681-683`) и `_show_library`
    (`:510-511`) так и делают. Любой новый вызов, забывший про `set_active`,
    рассинхронизирует подсветку. Перенести `set_active` внутрь
    `_on_section_changed`.

## Инструкция для ИИ-агента

**Роль.** Ты чинишь UI/UX-дефекты в PyQt6-приложении Whispered. Перед началом
прочитай `CLAUDE.md` — его правила приоритетнее этой инструкции.

**Порядок работы.**

1. Сначала воспроизведи дефект — отрисуй галерею и посмотри на конкретный PNG.
   Не чини «по описанию»: половина пунктов здесь про геометрию, и глазами
   видно то, чего не видно в коде.
2. Бери **один пункт за раз**, в порядке P0 → P1 → P2. Правила проекта:
   один шаг — один коммит (`fix:` для P0/P1, `refactor:`/`feat:` для P2).
   Не смешивать рефакторинг с исправлениями.
3. После каждого пункта — прогнать гейт целиком (см. ниже) и **пересобрать
   галерею**, сравнив «до/после» на том же файле.

**Обязательный гейт перед коммитом** (из `CLAUDE.md`):

```bash
ruff check .
python -m pytest tests/ -q
python -m compileall -q . -x '.venv|.claude|build|dist|docs/archive'
python -m mypy --ignore-missing-imports core/ transcriber.py diarizer.py exporters.py utils.py config.py
QT_QPA_PLATFORM=offscreen .venv/bin/python -m pytest tests_qt/ -q
.venv/bin/python tools/render_ui_gallery.py --output /tmp/whispered-ui-gallery --check
```

Флаг `--check` в галерее уже проверяет клиппинг — используй его, он для этого
и написан.

**Ограничения, которые нельзя нарушать.**

- Ничего длиннее ~100 мс в UI-потоке; вся фоновая работа — через
  `core/base_worker.py`, общение только сигналами Qt.
- Цвета и отступы берутся **только** из `ui/theme.py` (`Theme`, `SPACE_*`).
  Не вписывать хекс-константы в виджеты — половина дефектов P1 именно из-за
  того, что цвет объявлен мимо системы токенов.
- Новые поля настроек — только через `Config` (`config.py`) со значением по
  умолчанию.
- Не расширять область правки: пункты 11-16 — отдельные задачи, не тащить их
  в коммит по P0.

**Приёмка по каждому пункту.** Дефект считается закрытым, только если:
(а) есть скриншот «после», где его нет; (б) проверены **все три** размера
окна (900×550, 1100×700, 1440×900) и **обе** темы; (в) для текстовых дефектов
проверены обе локали — русский длиннее английского и режется первым;
(г) гейт зелёный.

**Что стоит закрыть регрессионным тестом** (в `tests_qt/`, там уже есть
smoke-каркас): пункт 1 (сайдбар после resize), пункт 2 (видимость
`file_list`/`empty_state` при нуле элементов) и пункт 4 (`summary_label`
не шире своего контейнера). Это три дефекта, которые проверяются
программно за пару строк и легко возвращаются обратно.
