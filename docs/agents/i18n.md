# i18n and live language switching

Read before adding or changing any user-visible string, `locales/*.json`,
plural counts or list dates.

- The UI language switches at runtime with no restart:
  `core.i18n.set_locale()` reloads the strings and fires every callback
  registered via `core.i18n.on_language_changed` (weak refs — pass a bound
  method or keep your own reference). The Settings dialog calls `set_locale()`
  on Apply/OK.
- Every widget that builds captions with `tr()` re-applies them on a language
  change through `ui.i18n_helpers.Retranslator`: wrap static captions with
  `self._i18n.text(widget, key[, setter][, tooltip=…])`, register a method for
  state-derived text with `self._i18n.call(self._retranslate_…)`, then call
  `self._i18n.bind()` once at the end of `__init__`.
- `MainWindow` and `RunView` keep their own `_retranslate()`, `SettingsDialog`
  its own `retranslate()`; extend those instead of adding a `Retranslator`.
- Modal dialogs opened with `.exec()` (recipe editor, provider dialog, model
  downloader, speaker rename, …) are rebuilt on each open and cannot coexist
  with the Settings dialog, so they are deliberately not retranslated.
- Transient strings (status-bar operation text, toasts, already-open message
  boxes) are not retranslated; they re-emit in the active language on next use.
- Counts go through `core.i18n.tr_count(key, n)` with `<key>_one/_few/_many`
  strings — Russian needs three forms ("1 запись, 2 записи, 5 записей").
- Dates in lists come from `core.date_format` (month names from the locale
  files), never `strftime("%b")`, which follows the C locale.
