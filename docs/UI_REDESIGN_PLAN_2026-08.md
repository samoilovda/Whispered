# План для ИИ-агента: редизайн UI/UX Whispered — «Рабочий стол» + гибрид

> Статус на 13 августа 2026: трёхколоночный workspace, Library, Inspector,
> checklist, status bar и Ctrl+K реализованы. Чекбоксы ниже сохраняют историю
> исходного плана и не являются актуальным трекером; состояние продукта
> фиксируется в `README.md` и `ROADMAP.md`.

> **Контекст.** Этот план реализует Вариант 2 «Рабочий стол» из
> [docs/UI_CONCEPT_2026-08.ru.md](UI_CONCEPT_2026-08.ru.md), выбранный
> пользователем 2026-08-12, с двумя заимствованиями: палитра команд Ctrl+K
> из Варианта 3 и явный чек-лист шагов вместо безымянного пресета из
> Варианта 1 (обоснование выбора — там же, §6.4 и §8). Диагноз проблем
> (§1), полный инвентарь функций, которые нельзя потерять (§2), и инварианты
> (§3) — см. концепт-документ, здесь не дублируются, только исполняются.
>
> Читать вместе с: `CLAUDE.md` (правила изменений, обязательный гейт),
> `docs/UI_UX_AUDIT_2026-08.md` (P0–P2 закрыты на момент написания — новый
> шелл не должен возвращать эти дефекты: элайдинг текста, компактные
> empty-state'ы, contrast-токены и т.д. переиспользуются как есть).
>
> Документ самодостаточен; выполняется фазами, каждая фаза оставляет
> приложение полностью рабочим и проходит гейт из `CLAUDE.md` целиком,
> включая `tests_qt/` offscreen-смоук и `render_ui_gallery.py --check`
> в обеих темах на всех трёх опорных размерах окна (900×550, 1100×700,
> 1440×900).

## 0. Принятые решения (не переобсуждаются в рамках плана)

1. Каркас — Вариант 2 «Рабочий стол»: три постоянные колонки (Библиотека /
   Документ / Инспектор), верхних разделов нет.
2. Из Варианта 3 берётся только палитра команд Ctrl+K поверх уже готового
   FTS — не берётся отказ от постоянного хрома или карточный поток.
3. Из Варианта 1 берётся только явный чек-лист шагов цепочки вместо
   анонимного пресет-комбо — не берётся степпер-навигация.
4. Стек остаётся PyQt6, без новых зависимостей и без QML (инвариант §3.10
   концепта).
5. `core/*` и движки не переписываются — меняется компоновка UI и точки
   входа (тот же принцип, что и в архивном
   `docs/archive/UI_REDESIGN_PLAN.md`).
6. Live остаётся за `Config.live_transcription_enabled` до прохождения
   Gate A/Gate B (`docs/LIVE_TRANSCRIPTION_PLAN.ru.md`) — план переносит её
   UI-точку входа, не расширяет готовность фичи.
7. Формат конфига и истории меняется только аддитивно (новые поля/колонки
   с дефолтами, старые записи читаются как есть).

## 1. Целевая информационная архитектура

```
┌─────────────┬──────────────────────────────┬───────────────┐
│ Записи   ＋▾ │ [Документ: черновик/запись]  │ ▤ ✦ ✂ 💬 ⚙   │
│ [поиск…]    │                               │ [раздел       │
│ Все·Файл·…  │                               │  инспектора]  │
│ (карточки)  │                               │               │
├─────────────┴──────────────────────────────┴───────────────┤
│ Статус-бар: операция · прогресс · Отмена | Очередь N ▴      │
│                                  ● LLM модель  🚀 GPU/CPU    │
└────────────────────────────────────────────────────────────┘
```

Полная раскладка и обоснование — концепт §6.2. Ключевое отличие от текущей
структуры: **Библиотека никогда не уходит с экрана** (сейчас
`_stack.setCurrentIndex(self._record_index)` полностью подменяет её —
`ui/main_window.py:525-528`), а создание новой записи происходит **в
центральном слоте** как черновик, а не через отдельную строку запуска на
отдельном экране.

### 1.1. Куда переезжает то, что есть сейчас

| Сейчас | Куда |
|---|---|
| `Sidebar` (Библиотека/Очередь/Диктофон/Live/Настройки) | Убирается как навигация между экранами. Настройки — кнопка ⚙ в шапке инспектора (Ctrl+, работает как сейчас). Очередь — всплывающая панель по клику на индикатор в статус-баре. Диктофон/Live — пункты меню `＋` |
| `LibraryView` (поиск, фильтры, список) | Левая колонка, растянута на всё время работы окна |
| `RecordView` + `_stack.setCurrentIndex` | Центр; больше не «страница взамен Библиотеки» — сама Библиотека остаётся слева |
| `LaunchBar` (файл, пресет, Обработать) | Открытая форма источника+параметров в центре у черновика (см. Фазу D) |
| `TranscribeOptionsPopover` | Вкладка «Параметры» инспектора у черновика (Фаза D) |
| `ToolWorkspace` (комбобокс 6 инструментов) | Иконочный рельс инспектора (Фаза A) |
| `BatchPanel` (Очередь) | Задания общей очереди; книжный батч — второй тип задания той же очереди (Фаза C) |
| `RecorderWidget` (раздел «Диктофон») | Источник из `＋` (Фаза D) |
| `LiveView` (раздел «Live») | Источник из `＋`, сетап/диагностика — в инспекторе (Фаза E) |
| `OperationBar` + `ProgressTimeline` + прогресс в `book_panel`/`batch_panel`/`ai_panel`/`insights_panel`/вкладках YouTube | Одна поверхность в статус-баре (Фаза C) |
| GPU/CPU-бейдж | Статус-бар (без изменений по месту, сейчас уже там) |
| `launch_preset` комбо (`ui/launch_bar.py`) | Чек-лист шагов на вкладке «Параметры» (Фаза D.3) |
| Поиск по FTS + фильтры (`library_view.py`) | Остаются в левой колонке; дублируются в палитре Ctrl+K (Фаза F) |
| `record_view.py:_build_export_menu` | Кнопка ⤓ в шапке документа, без изменений по сути |

Полная таблица по всем функциям — концепт §9, столбец «2 Рабочий стол».

## 2. Технический каркас

### 2.1. Новые файлы

```
ui/inspector_rail.py     — иконочный рельс + QStackedWidget разделов
                            (Материалы/Инсайты/Монтаж/Чат/Параметры),
                            заменяет ToolWorkspace; сигнал
                            section_changed(str), сворачиваемый
                            (переиспользует Config.record_tools_width)
ui/workspace_shell.py     — три колонки: LibraryView | центр | InspectorRail;
                            владеет сплиттером и правилами отзывчивости
                            (узкое окно — см. Фазу G)
ui/draft_record.py        — центральное содержимое для ещё нерасшифрованной
                            записи: сегментированный переключатель источника
                            (Файл/Диктофон/Live/Папка) + место под форму;
                            после первого результата уступает место
                            существующему плееру+транскрипту
ui/status_bar.py          — единая инфраструктурная полоса: текущая
                            операция+прогресс+Отмена, всплывающая очередь,
                            индикатор LLM с именем модели, GPU/CPU
ui/command_palette.py     — Ctrl+K: записи (FTS), действия, файлы
                            (Фаза F, поверх готового `core/history.py`)
ui/step_checklist.py      — явный чек-лист «что сделать после расшифровки»
                            вместо `launch_preset` комбо (Фаза D.3)
```

### 2.2. Что переиспользуется без переписывания

`TranscriptView`, `CleanedTextView`, `ArticleView`, `ChatPanel`,
`InsightsPanel`, `YouTubePanel`, `CutView`, `PlayerWidget`,
`RecorderWidget`, `LiveView` (как содержимое, не как раздел),
`BatchPanel` (как ядро общей очереди), `SettingsDialog`, `ProviderDialog`,
`TranscribeOptionsPopover` (переносится как содержимое вкладки, не как
поповер), вся `core/*` и движки. `RecordView.set_content_widgets` и
`_build_export_menu` — без изменений. Меняется компоновка и то, кто кем
владеет, не внутренняя логика панелей.

### 2.3. Что уходит

`ui/sidebar.py` как навигационный виджет между разделами — логика
`_SIDEBAR_FORCE_COLLAPSE_WIDTH`/`collapsed_changed` переезжает в
`workspace_shell.py` как правило отзывчивости колонок (Фаза G), сам класс
удаляется после Фазы B, когда `MainWindow` перестаёт держать
`QStackedWidget` разделов. `ui/launch_bar.py` и `ToolWorkspace` удаляются
после Фазы D/A соответственно, когда их функциональность полностью
переехала.

### 2.4. Конфиг

Новые поля `Config` (все с дефолтами, старые конфиги читаются как есть):

```python
inspector_section: str = "materials"   # последний открытый раздел инспектора
inspector_collapsed: bool = False      # аналог sidebar_collapsed для рельса
chain_steps: list = field(default_factory=lambda: ["transcript"])
                                        # чек-лист вместо launch_preset;
                                        # значения — те же артефакты, что
                                        # сейчас различает launch_preset
library_collapsed: bool = False        # форс-коллапс левой колонки на узком окне —
                                        # отдельно от inspector, т.к. правила
                                        # сжатия у колонок разные (см. Фазу G)
```

Поле `launch_preset` помечается deprecated (не читается новым UI), но не
удаляется — старые конфиги грузятся, значение конвертируется в
`chain_steps` один раз при первом запуске новой версии (Фаза D.3, миграция
без потери данных пользователя).

### 2.5. Схема истории

Артефакт-чипы уже пишутся в записи истории (поле `artifacts`, добавлено в
редизайне 2026-07) — новых миграций схемы не требуется для Фаз A–D. Фаза C
(одна очередь) добавляет тип задания: `ALTER TABLE queue_jobs ADD COLUMN
job_kind TEXT NOT NULL DEFAULT 'transcribe'` (или эквивалент, в зависимости
от реальной текущей схемы `BatchItem`/`BookBatchWorker` — свериться с кодом
перед миграцией, эта схема в плане не проверялась построчно).

## 3. Фазы выполнения

Каждая фаза — серия мелких коммитов (`feat:`/`refactor:`/`fix:`, один шаг —
один коммит, как требует `CLAUDE.md`). После каждой фазы: `ruff` чистый,
`pytest tests/` зелёный, `compileall` чистый, `mypy` по перечисленным в
`CLAUDE.md` модулям чистый, `tests_qt/` offscreen-смоук зелёный,
`render_ui_gallery.py --check` без клиппинга в обеих темах на 900×550 /
1100×700 / 1440×900. Каждая фаза — отдельная ветка/серия коммитов поверх
`main`, сливается только когда приложение полностью рабочее (партиальные
состояния не мержатся).

### Фаза A — Инспектор вместо комбобокса (низкий риск, независимая)

Самая маленькая и изолированная фаза — хороший разогрев, ничего не ломает
структурно.

1. `feat: add InspectorRail widget` — `ui/inspector_rail.py`: иконочный
   рельс (переиспользует паттерн `Sidebar._make_nav_button`) +
   `QStackedWidget`; API-совместим с `ToolWorkspace.addTab`/`setCurrentIndex`
   настолько, насколько возможно, чтобы Фаза A не трогала
   `RecordView.set_content_widgets`.
2. `feat: show artifact-ready dots on inspector rail items` — точка/галочка
   на пункте рельса, если материал уже сгенерирован (источник данных —
   тот же, что питает чипы Библиотеки).
3. `refactor: replace ToolWorkspace with InspectorRail in RecordView` —
   замена в `ui/record_view.py`; `ToolWorkspace` удаляется, если больше нет
   потребителей (`grep -rn "ToolWorkspace" ui/`).
4. Приёмка: экран Записи выглядит и работает как сейчас, но переключение
   инструментов — рельсом с иконками и статусом готовности, а не
   комбобоксом. `record_tools_width` по-прежнему определяет ширину панели.

### Фаза B — Постоянная Библиотека (структурная, средний риск)

Сердце редизайна: Библиотека перестаёт исчезать при открытии записи.

1. `feat: add WorkspaceShell with persistent library column` —
   `ui/workspace_shell.py`: `QSplitter` из трёх зон; левая — существующий
   `LibraryView` как есть (поиск/фильтры/список без изменений), центр —
   пока просто существующий `RecordView` (без изменений содержимого),
   правая — `InspectorRail` из Фазы A.
2. `refactor: MainWindow hosts WorkspaceShell instead of QStackedWidget
   sections` — `library`/`recorder`/`live` перестают быть страницами
   `_stack`; `_stack` в `MainWindow` для разделов удаляется. `Queue` и
   `Settings` пока остаются как есть (уходят в Фазах C/готовы уже сейчас) —
   допустимое временное состояние внутри фазы, но не в точке слияния фазы.
3. `refactor: open_record updates the center pane, library stays visible` —
   `library_view.open_record` теперь не переключает индекс `_stack`
   (которого больше нет), а меняет содержимое центра; список слева не
   перерисовывается и не теряет позицию скролла/выделения.
4. `feat: highlight the open record in the library list` — открытая запись
   подсвечена в списке слева (сейчас это неприменимо, т.к. список и
   документ никогда не видны одновременно).
5. `refactor: retire Sidebar as section navigation` — `ui/sidebar.py`
   удаляется; кнопка «⚙ Настройки» переезжает в шапку инспектора/шапку
   документа; хоткеи `Ctrl+1..3` (`ui/main_window.py:692-694`) — см. Фазу G
   (полная ревизия хоткеев, не трогать здесь точечно).
6. Приёмка (сквозной сценарий): открыть запись из истории → список слева
   виден, документ в центре, инспектор справа; кликнуть другую запись в
   списке без «← Библиотека» — она открывается в центре напрямую; закрыть
   приложение и открыть заново — восстанавливается пустое состояние центра
   (ничего не открыто), список на месте.

### Фаза C — Единая поверхность прогресса и одна очередь

1. `feat: add unified StatusBar widget` — `ui/status_bar.py`: операция +

3. `feat: single LLM status source` — единая проверка доступности LM

5. `refactor: retire per-panel progress surfaces` — удалить дублирующиеся

6. Приёмка: запустить одновременно транскрипцию файла и книжный батч по

Самая рискованная по бизнес-логике фаза — трогает `_start_batch_processing`

1. `feat: add DraftRecord widget for the center pane` —
   `ui/draft_record.py`: сегментированный переключатель источника

   поповера на Библиотеке; `_start_batch_processing()` перестаёт читать

3. `feat: replace launch_preset combo with explicit chain_steps checklist`

   ☐ инсайты ☐ книга`; хранится в `Config.chain_steps` (см. §2.4);

   Оркестрация цепочки (`_finish_preset_chain` и связанные хендлеры в

4. `feat: RecorderWidget/LiveView mount inside DraftRecord as sources` —
   для «Диктофон»/«Живая» переключатель источника разворачивает
   существующие виджеты внутри черновика, а не на отдельном экране (для
   Live это переходное состояние — полная интеграция в Фазе E).
5. `refactor: DraftRecord hands off to RecordView content after first
   result` — после завершения расшифровки центр показывает
   плеер+транскрипт (существующие виджеты), черновик закрывается; запись

6. `refactor: retire LaunchBar` — `ui/launch_bar.py` удаляется, когда не

7. Приёмка (сквозной сценарий, как в архивном плане §4 Фаза C.5): `＋` →

   показывает оба результата. Параметры и чек-лист пережили перезапуск.

### Фаза E — Live как источник, а не раздел

1. `feat: fold Live setup/preflight/diagnostics into inspector "Параметры"
   for a live draft` — существующая логика `LiveView` (сетап, preflight,
   метрики, диагностика, баннеры) переносится как содержимое, не как
   отдельный экран; результат с первой секунды пишется как обычная запись
   (чекпоинты уже это делают, см. `LiveCheckpointTracker`).
2. `refactor: retire LiveView as a top-level page` — `ui/live_view.py`
   остаётся файлом с виджетами (переиспользуются), но не смонтирован как
   раздел `MainWindow`.
3. Приёмка: `＋` → «Живая» → сетап в инспекторе → старт → растущий
   транскрипт в центре → стоп → запись в истории как обычная, со всеми
   чипами. Это не расширяет готовность Live-фичи (флаг
   `live_transcription_enabled` работает как раньше) — только переносит
   точку входа существующего пути.

### Фаза F — Палитра команд Ctrl+K (заимствование из Варианта 3)

Независима от Фаз C–E по коду, но по продукту логичнее делать её после
слияния Библиотеки (Фаза B), чтобы индексировать финальный список действий.

1. `feat: add CommandPalette widget` — `ui/command_palette.py`: модальный
   оверлей, список = записи (существующий FTS из `core/history.py`,
   без изменений схемы) + статический реестр действий («сгенерировать
   YouTube», «экспорт SRT», «начать живую запись», «открыть настройки» —
   и т.д., см. концепт §7.2 для полного духа списка) + недавние файлы.
2. `feat: bind Ctrl+K, wire action registry to existing handlers` —
   действия палитры вызывают те же слоты, что и текущие кнопки/хоткеи, не
   дублируют логику.
3. Приёмка: Ctrl+K из любого места приложения; ввод части имени записи или
   действия сужает список за счёт уже существующего FTS-ранжирования;

## 5. Чего не делать

- Не строить полный Pipeline Engine ради чек-листа (§3.7 концепта уже это
  запрещает) — чек-лист остаётся последовательным запуском существующих
  воркеров.
- Не переписывать `core/*` и движки — только UI-слой и тонкая оркестрация
  сигналов; единственные исключения — миграция схемы очереди (§2.5) и
  одноразовая миграция `launch_preset` → `chain_steps` (Фаза D.3), обе
  аддитивные.
- Не уходить в QML/веб-виджеты, не добавлять зависимостей.
- Не превращать Настройки (Ctrl+,) в третье место для параметров
  прогона — там только умолчания, подписаны явно как умолчания.
- Не расширять готовность Live-функциональности под предлогом переноса её
  точки входа — Gate A/Gate B остаются отдельной, непройденной работой.
- Не мержать фазу, если сквозной сценарий приёмки этой фазы не проверен
  вручную хотя бы один раз (скриптованные проверки обязательны, но не
  заменяют один реальный прогон на реальных данных на фазу).
- Не пушить в удалённые ветки без отдельной просьбы (действующее правило
  сессии).
