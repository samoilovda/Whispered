## 1. Диагноз: почему нужен второй заход

Прошлый редизайн решил главную проблему 2026-07 («восемь вкладок и
переключатель режимов») и сделал Библиотеку первым экраном. Но объём
функциональности с тех пор вырос — YouTube-пакет, инсайты, чат, книжный
пайплайн, нарезка видео, живая транскрипция — и структура, рассчитанная
на «транскрипт + статья», под этим весом расползлась. Ниже — только то,
что видно в коде, без домыслов.

### 1.1. Одиннадцать разных механизмов переключения

Чтобы добраться до контента, пользователь последовательно применяет
разные, ничем не связанные идиомы:

| Механизм | Где |
|---|---|
| Иконочный рельс (exclusive `QToolButton`) | `ui/sidebar.py` |
| `QStackedWidget` без видимого селектора | `main_window.py:_stack` |
| Полоса вкладок | `main_tabs` (Транскрипт / Чистовик) |
| **Выпадающий список как навигация** | `ToolWorkspace.selector` — 6 инструментов |
| Вторая полоса вкладок | `youtube_panel` — 5 подвкладок |
| Третья полоса вкладок | `article_view` — 5 форматов |
| Меню | `record_view` — Экспорт ▾ |
| Поповер | `transcribe_options` — 5 параметров |
| Список категорий | `settings_dialog` — 5 разделов |
| Ряд чипов-фильтров | `library_view` |
| Сплиттеры | `record_view`, `cut_view` |

Самое дорогое здесь — `ToolWorkspace`: шесть инструментов (Статьи, Чат,
Инсайты, Нарезка, YouTube, Книга) спрятаны в `QComboBox`. Комбобокс не
показывает, что внутри, и не показывает, что там уже готово, — это худший
из возможных способов навигации по равноправным разделам.

**Максимальная глубина** — 4 селектора до «Тегов YouTube»:
сайдбар → карточка записи → комбобокс инструментов → вкладка «Теги».
Мест, где может спрятаться контент, — около 28.

### 1.2. Один экран решает две несвязанные задачи

Библиотека — это одновременно «запусти новую работу» (`FormSection` с
launch bar и file selector) и «посмотри прошлые». Верхний блок занимает
фиксированную высоту всегда, даже когда пользователь пришёл просто найти
запись двухнедельной давности. И наоборот: открыв запись, пользователь
полностью теряет список — вернуться можно только кнопкой «← Библиотека».

### 1.3. Неявные связи: параметры прогона живут не там, где прогон

`_start_batch_processing()` читает `self.model_combo`, `self.language_combo`,
`self.perf_combo`, `self.diarization_checkbox` — то есть **значения из
поповера на странице Библиотеки**. Пользователь на странице «Очередь» не
видит ни одного из этих контролов, но они определяют, как обработается
папка. То же с бейджем GPU/CPU: он существует только в шапке Библиотеки, а
влияет и на очередь. Книжный батч по папке — третий потребитель тех же
скрытых настроек.

### 1.4. Дублирование входов и поверхностей

- **Три способа запустить генерацию:** кнопки «Чистовик»/«Статьи» в шапке
  Записи, собственная кнопка «Сгенерировать» внутри каждой панели, и
  автоматическая пресет-цепочка. Плюс `AIProcessingPanel`, который
  создаётся, обрабатывает сигналы — и `setVisible(False)`: невидимый UI как
  контроллер.
- **Шесть поверхностей прогресса:** `OperationBar` + `ProgressTimeline`
  (глобальные), `book_panel.batch_progress`, `batch_panel` прогресс,
  `ai_panel` прогресс, состояние кнопки в `insights_panel`, состояние
  вкладок в `youtube_panel`.
- **Две независимые очереди:** `BatchPanel` (транскрипция папки) и
  скрытая внутри `BookPanel` вторая очередь (`BookBatchWorker`, обработка
  папки текстов) — с собственным пикером папки, счётчиком и прогрессом.
- **Два места для параметров:** поповер (значения прогона) и Настройки
  (умолчания). Визуальной связи между ними нет — пользователь не понимает,
  какое из двух победит.
- **Два места для очистки истории:** меню «⋯» в Библиотеке и кнопка в
  Настройках.
- **Настройки отображения не там, где текст:** таймкоды и метки спикеров
  переключаются в Настройках, хотя относятся к панели транскрипта.

### 1.5. Доступность ИИ невидима до момента отказа

Локальная LLM может быть не запущена. Сейчас это выясняется по-разному:
`insights_panel` показывает «нет LM» на своём месте, `book_panel` держит
собственный таймер проверки соединения, Настройки предлагают «Проверить
соединение», а Чат/Статьи/YouTube просто падают в ошибку по нажатию.
Единого индикатора «LLM: подключена, модель X» в интерфейсе нет.

### 1.6. Живая транскрипция — параллельная вселенная

`LiveView` — это отдельный экран со своим сетапом, preflight, метриками,
диагностикой, баннерами и своим представлением транскрипта. При этом её
результат — обычная запись в истории (чекпоинты уже пишутся). То есть
концептуально Live — это **источник аудио**, такой же как файл, микрофон и
папка, а в UI это пятая страница верхнего уровня со своей логикой.

## 2. Что обязано сохраниться (инвентарь)

Ни один вариант ниже не убирает функции. Полный список того, что должно
остаться достижимым:

**Источники:** локальный файл (кнопка + drag&drop на любом экране), запись
с микрофона (выбор устройства, уровень, таймер), живой захват (микрофон и/или
системный звук, выбор цели, preflight, пауза/стоп, метрики, диагностика),
папка для пакетной обработки.

**Параметры прогона:** модель whisper, язык, перевод →EN, режим
производительности, диаризация (+ число спикеров, HF-токен), GPU/CPU,
пользовательский словарь.

**Расшифровка:** прогресс по 6 стадиям, ETA, отмена; редактируемый
транскрипт с поиском, переименованием спикеров, таймкодами, копированием;
плеер (±10 с, слайдер, скорость 0.5–2×) синхронизированный с текстом.

**Материалы:** чистовик (статистика по филлерам/абзацам), статьи в 5
форматах, YouTube-пакет (таймкоды, заголовки, описание, теги, ключевые
вопросы; язык генерации; провайдер LM Studio / OpenAI / Anthropic),
инсайты (главы, задачи, ключевые моменты с переходом по времени), чат с
транскриптом (быстрые вопросы), книжный пайплайн (unwrap + кастомный
промпт + батч по папке).

**Видео:** чек-лист сегментов, отметка пауз по порогу, экспорт EDL,
сборка черновика MP4.

**Выгрузка:** 9 форматов экспорта с запоминаемым мультивыбором,
автосохранение артефактов пресет-цепочки в `output/<stem>/`.

**Библиотека:** FTS-поиск, фильтры по типу источника, чипы готовности
артефактов, удаление записи, очистка всей истории.

**Прочее:** пресеты-цепочки, 5 категорий настроек, темы, RU/EN, тосты,
пустые состояния, хоткеи.

## 3. Инварианты: правила, общие для всех трёх вариантов

Это не варианты выбора, а условия приёмки любого из них.

1. **Одна поверхность прогресса.** Все шесть текущих сводятся в одну
   операционную область; панели сообщают прогресс сигналами, а не рисуют
   свои полоски.
2. **Статус LLM и устройства видны всегда.** Действие, для которого нет
   LLM, показано как недоступное с объяснением — а не падает в ошибку по
   нажатию.
3. **Параметры прогона живут там, где запускается прогон,** и одни и те же
   для файла, очереди и книги. Скрытая связь «поповер Библиотеки → Очередь»
   устраняется.
4. **Один вход в каждое действие.** «Сгенерировать статьи» — из одного
   места, а не из трёх. Невидимый `AIProcessingPanel` разбирается на явный
   контроллер без виджета.
5. **Никаких вложенных полос вкладок.** Внутри рабочей области — максимум
   один уровень переключения. Пять подвкладок YouTube и пять форматов
   статей становятся секциями/аккордеоном.
6. **Настройки отображения — рядом с содержимым.** Таймкоды и спикеры
   переключаются в панели транскрипта (значение остаётся в `Config`).
7. **Одна очередь.** Книжный батч по папке становится типом задания общей
   очереди.
8. **Live — источник, а не раздел.** Её сетап/preflight/диагностика
   остаются как есть, но живут внутри выбора источника, а результат с
   первой секунды является обычной записью.
9. **Пустое состояние объясняет следующий шаг** в каждой области, где
   контента ещё нет.
10. **Технические рамки без изменений:** PyQt6 без новых зависимостей и без
    QML; все строки через `tr()` с синхронными `locales/en.json` и
    `locales/ru.json`; обе темы; рабочее окно от 900×550; движки и `core/*`
    не переписываются — меняется компоновка и точки входа; миграция фазами,
    каждая фаза оставляет приложение полностью рабочим и проходит
    pre-commit gate из CLAUDE.md, включая `tests_qt/` offscreen-смоук на
    новый шелл.

## 4. Почему именно эти три варианта

Перегруженный интерфейс — это всегда несоответствие между структурой UI и
тем, что пользователь держит в голове. Держать он может ровно одно из трёх:

- **процесс** — «я веду запись через этапы» → Вариант 1 «Конвейер»;
- **объект** — «у меня есть записи, я с ними работаю» → Вариант 2
  «Рабочий стол»;
- **действие** — «я знаю, что хочу сделать» → Вариант 3 «Полотно».

Это исчерпывающий набор: любой четвёртый вариант окажется смесью этих
трёх. Они же различаются по целевому пользователю (эпизодический новичок /
ежедневный контент-редактор / клавиатурный power user), по объёму работ
(средний / малый / большой) и по риску. Поэтому выбор между ними —
осмысленное продуктовое решение, а не вкусовое.

## 5. Вариант 1 — «Конвейер» (организация по этапу)

### 5.1. Идея

Верхний уровень — не разделы приложения, а **этапы работы над одной
записью**. Степпер этапов служит одновременно навигацией и индикатором
прогресса, поэтому `ProgressTimeline` и навигация — один объект, а не два.
Набор этапов адаптивный: «Монтаж» появляется только для видео.

### 5.2. Экраны

Дом — Библиотека во всю ширину (список наконец получает весь экран):

```
┌────────────────────────────────────────────────────────────┐
│  Записи                        [＋ Новая запись ▾]    ⚙   │
│  [поиск……………………]  Все · Файл · Диктофон · Живая           │
│  ┌──────────────────────────────────────────────────────┐  │
│  │ 🎬 С Валерией Ворониной        31:21   вчера         │  │
│  │    ✓ транскрипт  ✓ YouTube  ○ статья  ○ инсайты      │  │
│  ├──────────────────────────────────────────────────────┤  │
│  │ 🎙 audio1170954204             48:41   8 июл         │  │
│  │    ✓ транскрипт                                      │  │
│  └──────────────────────────────────────────────────────┘  │
├────────────────────────────────────────────────────────────┤
│  Очередь: 3 · Расшифровка 2/3 · 41 %      ● LLM  🚀 GPU    │
└────────────────────────────────────────────────────────────┘
```

Клик по записи (или по её чипу — тогда сразу на нужный этап) открывает
конвейер:

```
┌────────────────────────────────────────────────────────────┐
│ ←  С Валерией Ворониной                          [Экспорт ▾]│
│ ①Источник ─ ②Расшифровка ─ ③Материалы ─ ④Монтаж ─ ⑤Выгрузка│
│    ✓           ✓            2 из 5      (видео)            │
├────────────────────────────────────────────────────────────┤
│                                                            │
│   [содержимое активного этапа во всю ширину]               │
│                                                            │
├────────────────────────────────────────────────────────────┤
│  Готово · 12 480 слов                     ● LLM  🚀 GPU    │
└────────────────────────────────────────────────────────────┘
```

**① Источник.** Сегментированный переключатель `Файл · Диктофон · Живая ·
Папка` — четыре текущих способа ввода в одном месте. Ниже — параметры
прогона **открытой формой**, а не поповером: на этом этапе они и есть
содержимое экрана, прятать их незачем. Здесь же — GPU/CPU и «Что сделать
после расшифровки»: не безымянный пресет, а явный чек-лист
(`☑ транскрипт ☑ YouTube-пакет ☐ статья ☐ инсайты ☐ книга`), который
запоминается. Для «Живая» разворачивается существующий сетап с preflight и
диагностикой; для «Папка» экран превращается в редактор задания очереди.

**② Расшифровка.** Плеер + транскрипт во всю ширину. Переключатели
таймкодов/спикеров и переименование — здесь. Отдельный вид «Чистовик» —
сегментированный переключатель `Транскрипт ⇄ Чистовик` (два элемента, это
допустимо).

**③ Материалы.** Один скроллящийся экран из секций (`CollapsiblePanel`
уже есть в `ui/components.py`): Чистовик, Статьи, YouTube-пакет, Инсайты,
Книга. Каждая секция — либо результат, либо строка «не создано
[Сгенерировать]». Никаких вкладок: пять подвкладок YouTube становятся
пятью блоками внутри одной секции. Слева — липкий указатель секций. Чат —
выдвижная панель поверх (это диалог, а не артефакт).

**④ Монтаж** (только для видео). Чек-лист сегментов, отметка пауз, EDL,
сборка черновика.

**⑤ Выгрузка.** Форматы, что уже сгенерировано, куда сохранится, кнопка.

Очередь — не раздел, а лоток в статус-баре: индикатор «Очередь: 3» открывает
список задач. Пакетная обработка — это N конвейеров, идущих без участия
пользователя.

### 5.3. За и против

**За.** Совпадает с задокументированным ежедневным сценарием (файл →
транскрипт → YouTube-пакет / статья) и обучает себе сам: пользователь
никогда не спрашивает «куда дальше». Навигация и прогресс — один объект.
Скрытых связей нет по построению: параметры видны на том же экране, где
кнопка запуска. Адаптивные этапы убирают ненужное (для аудио нет
«Монтажа»). Материалы-секции масштабируются на новые типы артефактов без
пересборки навигации. Глубина падает до 2 селекторов, механизмов
переключения остаётся ~4.

**Против.** Открыть транскрипт старой записи — на клик дольше (лечится
переходом сразу на этап по клику в чип). Этап «Материалы» на длинной
записи становится очень высоким скроллом. Степпер легко ошибочно
прочитать как визард — обязательна свободная навигация по уже пройденным
этапам и явное «этап доступен/недоступен». Библиотека исчезает, когда
запись открыта (как и сейчас).

**Объём:** средне-высокий. Нужны новый шелл (степпер + контейнер секций),
лоток очереди, интеграция Live как источника. Панели переиспользуются как
тела секций.
**Главный риск:** интеграция Live — она за флагом и не стабилизирована;
её сетап переносится целиком, без переписывания.

## 6. Вариант 2 — «Рабочий стол» (организация по объекту) ★ рекомендуется

### 6.1. Идея

Верхних разделов нет вообще. Одно окно, три колонки, всё время на экране:
слева — библиотека, в центре — открытая запись, справа — инспектор
инструментов. Создание новой записи происходит **в том же центральном
слоте**: новая запись — это черновик, который сначала показывает форму
источника и параметров, а после расшифровки на том же месте показывает
транскрипт. Навигации при этом не происходит вообще.

### 6.2. Экран

```
┌─────────────┬──────────────────────────────┬───────────────┐
│ Записи   ＋▾ │ С Валерией Ворониной         │ ▤ ✦ ✂ 💬 ⚙   │
│ [поиск…]    │ ▶──────●───────── 21:05/31:21│ ── Материалы ─│
│ Все·Файл·…  │ ┌ Транскрипт │ Чистовик ┐    │ Чистовик    ✓ │
│ ─────────── │ │ 00:00 Спикер 1: …      │   │ Статьи      ○ │
│ ● (черновик)│ │ 00:12 Спикер 2: …      │   │  [Создать]    │
│ ○ С Валерией│ │                        │   │ YouTube     ✓ │
│   ✓тр ✓yt   │ │                        │   │  Таймкоды ⌄   │
│ ○ audio1170…│ │                        │   │  Заголовки ⌄  │
│   ✓тр       │ │                        │   │  Описание ⌄   │
│ ○ Zoom 12.07│ │                        │   │  Теги ⌄       │
│   ✓тр ✓инс  │ │                        │   │  Вопросы ⌄    │
│             │ │                        │   │ Инсайты     ○ │
│             │ └────────────────────────┘   │ Книга       ○ │
├─────────────┴──────────────────────────────┴───────────────┤
│ Расшифровка · 41 % · ETA 2:10 · [Отмена]  Очередь 3 ▴      │
│                                    ● LLM gemma-4  🚀 GPU   │
└────────────────────────────────────────────────────────────┘
```

**Левая колонка — библиотека, всегда.** Поиск, фильтры, чипы готовности.
Записи не «открываются вместо» списка — список не уходит никогда. Кнопка
`＋` даёт четыре источника (файл / диктофон / живая / папка) и создаёт
черновик прямо в списке.

**Центр — документ.** Плеер сверху, транскрипт под ним, единственный
переключатель `Транскрипт ⇄ Чистовик`. Правка, поиск, переименование
спикеров, таймкоды/спикеры — здесь.

**Правая колонка — инспектор** с иконочным рельсом (Материалы, Инсайты,
Монтаж, Чат, Параметры). Рельс заменяет комбобокс `ToolWorkspace`:
разделы видны сразу, а галочки/точки показывают, что уже готово.
Внутри «Материалов» — аккордеон (Чистовик, Статьи, YouTube, Книга), где
пять подвкладок YouTube и пять форматов статей стали раскрывающимися
блоками. Инспектор сворачивается; ширина уже сохраняется в
`Config.record_tools_width`.

**⚡ «Сгенерировать»** в шапке записи — единый список всех генераций со
статусом (`✓ готово` / `— нет` / `⚠ нужна LLM`) плюс «Запустить цепочку…».
Это тот самый единственный вход из инварианта 4.

**Статус-бар становится инфраструктурой:** текущая операция + прогресс +
отмена, всплывающая **очередь (N)** — одна на всё приложение, индикатор
**LLM** с именем модели, переключатель GPU/CPU. Шесть поверхностей
прогресса и четыре способа узнать о статусе LLM сводятся сюда.

**Параметры прогона** — вкладка «Параметры» инспектора у черновика. Пока
запись не расшифрована, инспектор открыт именно на ней; параметры
принадлежат записи, а не глобальному окну, поэтому связь «настройки одной
страницы влияют на другую» исчезает физически. Настройки (Ctrl+,) остаются
диалогом умолчаний и явно подписаны как умолчания.

**Живая запись** — источник из `＋`: центральная колонка показывает
растущий транскрипт, сетап и диагностика идут в инспекторе. Никакой
отдельной страницы.

### 6.3. За и против

**За.** Совпадает с реальным использованием: записей много, работа
итеративная, возврат к старым — норма. Библиотека перестаёт исчезать.
Ровно один мысленный образ на всё приложение — «список, документ,
инструменты», знакомый из почтовых клиентов и IDE. Механизмов
переключения ~5, глубина 2. Масштабируется: новый инструмент — новая
секция инспектора, навигация не меняется. И это **самый дешёвый путь из
текущего кода**: `LibraryView` и `RecordView` уже существуют, у Записи уже
есть сплиттер с инструментами — работа в основном сводится к слиянию двух
страниц, замене комбобокса на рельс и апгрейду статус-бара.

**Против.** Трём колонкам нужно ≥1100 px, чтобы дышать (минимум окна
сейчас 900) — обязательно правило отзывчивости: под ~1000 px библиотека
сворачивается в рельс/оверлей, инспектор — в кнопку. Плотно: риск
получить «профессионально-тяжёлый», а не спокойный вид — лечится воздухом
и тем, что инспектор по умолчанию открыт на одной секции, а не на всех.
Инспектор может снова стать чуланом — поэтому жёсткое правило: не более
пяти разделов, всё остальное уходит в меню ⚡.

**Объём:** средний, наименьший из трёх при наибольшей отдаче.
**Главный риск:** отзывчивость на узких окнах — её нужно спроектировать
сразу, а не «потом».

### 6.4. Почему рекомендуется этот

Он снимает все шесть пунктов диагноза, требует меньше всего переписывания
и не ломает ни одну существующую привычку: Библиотека остаётся первым и
главным экраном, пресеты остаются, панели остаются собой. Два элемента
стоит позаимствовать: **палитра Ctrl+K** из Варианта 3 (поверх уже
готового FTS — это дёшево и сразу делает все ~28 мест поиска доступными
одной строкой) и **явный чек-лист шагов цепочки** из Варианта 1 вместо
безымянного пресета. Это не компромисс ради компромисса: Вариант 2
определяет каркас, Вариант 3 добавляет указатель, Вариант 1 — модель
конфигурации прогона; оси не конфликтуют.

## 7. Вариант 3 — «Полотно» (организация по действию)

### 7.1. Идея

Радикальное сокращение хрома. Постоянного интерфейса почти нет: одна
центральная колонка контента, палитра команд (Ctrl+K) как основная
навигация, а результаты приходят **карточками**, добавляющимися в поток.
Вкладок нет нигде.

### 7.2. Экран

```
┌────────────────────────────────────────────────────────────┐
│ ⌘K Что сделать?              Записи ▾    ● LLM  🚀 GPU  ⚙ │
├────────────────────────────────────────────────────────────┤
│                                                            │
│   С Валерией Ворониной · 31:21 · RU · вчера                │
│   ▶ ────────────●─────────────────────  21:05 / 31:21      │
│                                                            │
│   ┌─ Транскрипт ───────────────────────────────────── ⌃ ┐  │
│   │ 00:00  Спикер 1: …                                  │  │
│   │ 00:12  Спикер 2: …                                  │  │
│   └─────────────────────────────────────────────────────┘  │
│   ┌─ YouTube-пакет · ✓ 5 материалов ─────────────────  ⌄ ┐ │
│   └─────────────────────────────────────────────────────┘  │
│   ┌─ Инсайты · не создано ──────────  [Сгенерировать]  ⌄ ┐ │
│   └─────────────────────────────────────────────────────┘  │
│   ＋ Добавить материал ▾        (статья · книга · монтаж)   │
│                                                            │
├────────────────────────────────────────────────────────────┤
│  Инсайты · 3 из 3 · готово                                 │
└────────────────────────────────────────────────────────────┘
```

- Всё — карточки в одном вертикальном потоке: Транскрипт, Чистовик,
  Статьи, YouTube, Инсайты, Книга, Монтаж. По умолчанию раскрыт только
  транскрипт. Отсутствующие материалы — либо строка «не создано
  [Сгенерировать]», либо скрыты за «＋ Добавить материал».
- Ноль полос вкладок: пять материалов YouTube — пять блоков внутри
  карточки, пять форматов статей — пять блоков.
- Навигация — палитра **Ctrl+K**: записи (FTS уже есть), действия
  («сгенерировать YouTube», «экспорт SRT», «начать живую запись»,
  «открыть настройки»), файлы. Библиотека — область поиска в палитре плюс
  выпадающий список «Записи ▾»; постоянного списка нет.
- Чат — нижняя выдвижная панель поверх потока, а не карточка.
- Прогресс — на самой карточке, которая генерируется, плюс тонкая линия
  сверху. Очередь — собственный поток карточек.
- Настройки — полноэкранная страница, не модальный диалог.

### 7.3. За и против

**За.** Наименьшая визуальная нагрузка из трёх: на экране почти только
контент — прямой ответ на «не перегружать интерфейс». Масштабируется
безгранично: любой новый артефакт — просто новый тип карточки, навигация
не меняется никогда. Палитра делает **весь** набор функций доступным
поиском — это честный ответ на «много функций, мало места»: 28 мест, где
может спрятаться контент, заменяются одним индексом. Отлично для узких
окон и ноутбуков. Клавиатурный сценарий становится основным, а не
побочным.

**Против.** Слабейшая обнаруживаемость для нового пользователя: палитра
невидима, и её приходится компенсировать явной кнопкой «＋ Добавить
материал» и подсказкой при первом запуске. Наименее «нативно-десктопный»
вид — часть пользователей Qt-приложений воспримет как веб. Наибольший
объём работ: контейнер карточек, движок палитры, перенос каждой панели в
обёртку-карточку, Настройки как страница. Доступность и клавиатура здесь
не «полировка», а обязательная часть.

**Объём:** высокий. Панели выживают как содержимое карточек, но каркас
пишется с нуля.
**Главный риск:** обнаруживаемость. Без хорошей работы над пустыми
состояниями и первым запуском мощные функции просто перестанут находиться.

## 8. Сравнение

| Критерий | 1 «Конвейер» | 2 «Рабочий стол» ★ | 3 «Полотно» |
|---|---|---|---|

| Кликов до «Тегов YouTube» (сейчас 4) | 2 | 2 | 1 |
| Работа с многими записями подряд | слабее | **лучшее** | среднее |

| Устойчивость к новым функциям | хорошая | хорошая | **лучшая** |
| Объём работ | средне-высокий | **средний** | высокий |

**Рекомендация:** Вариант 2 как каркас + палитра Ctrl+K из Варианта 3 +

максимальная отдача при наименьшем объёме переписывания и без потери
существующих привычек.

Если приоритет — приток новых пользователей и «понятно без обучения»,
выбирается Вариант 1. Если приоритет — минимализм и клавиатура для
ежедневного личного использования, выбирается Вариант 3.

## 10. Чего не делать ни в одном варианте

- Не переписывать движки и `core/*` — только UI-слой и тонкая
  оркестрация сигналов.
- Не строить полный Pipeline Engine ради интерфейса: чек-лист шагов —
  это те же существующие воркеры, запускаемые последовательно.
- Не уходить в QML/веб-виджеты и не добавлять зависимостей.
- Не делать Настройки третьим местом для параметров прогона: там только
  умолчания, и это должно быть подписано.
- Не менять форматы конфига и истории несовместимо — только аддитивные
  поля и колонки с дефолтами.
- Не трогать поведение по умолчанию: офлайн, тёмная тема, автосохранение
  истории, Live за флагом до прохождения Gate A/Gate B.
