## Подробности

**T12a — контраст.** В `Theme` добавлены текстовые роли `accent_text/success_text/warning_text/error_text/info_text`; все `color:` в QSS, тосты и диалог версий используют их, заливки/иконки — прежние токены. Тёмная тема: `text_secondary` `#888888→#a3a3a3`, `text_muted` `#666666→#949494`, accent `#6366f1→#5f62f0` (белый текст кнопки 4,47→4,68:1). Светлая: warning-текст `#8a5300` (было 1,93:1 для `#f9ab00`). Тест считает WCAG-контраст реальных пар, включая текст статус-бейджа на его подложке, и запрещает fill-токен в `color:`. Диалог версий больше не использует тёмные литералы в светлой теме.

**T01 — геометрия.** Галерея проверяет вертикальное обрезание (с `heightForWidth` для переносимых подписей) и пересечение соседей одного layout. Стартовый экран прокручивается вместо сжатия (скрытые страницы стека не задают высоту); у зоны drop убрано выравнивание layout, из-за которого `heightForWidth` занижался и иконка налезала на заголовок; панель транскрипта — `FlowLayout` с переносом, строки центрируются по высоте. В галерею добавлена заполненная запись: длинное RU/EN название, два спикера, четыре неуверенных фрагмента.

**T02 — готовность.** `domain.recipe.effective_provider()` — одно правило «кто выполняет шаг» для запуска (`application/steps.py`) и для готовности. Проверки: локальные LLM-шаги (с перечислением шагов), отдельный адрес LM Studio для книги («не проверен»), облачный пакет YouTube («ключ задан, соединение не проверено» — ключ не проверяется платным запросом). Пропускаемые шаги перечислены строкой «Будет пропущено: …» с явным действием «Только расшифровка»; рецепт сам не меняется. Отсутствие ffmpeg блокирует запуск с пояснением.

**T03 — импорт.** `application/import_sources.py`: папка раскрывается на один уровень, дубликаты (в т.ч. через папку) отбрасываются, нечитаемая папка не отменяет остальные источники, нелокальные URL считаются. Зона выбора файла передаёт все URL в общий `MainWindow.import_sources()`: один файл — стартовый экран, несколько — очередь. Генерация от drop не запускается.

**T04 — библиотека.** `HistoryStore.query_records(RecordQuery)`: фильтры источника и рецепта (последний прогон) применяются в SQL до `LIMIT`; стабильная сортировка с tie-breaker `id`; поиск — сначала совпадения по названию, затем FTS по релевантности; `matched`/`total`/`has_more`. В библиотеке — «Показать ещё», «Показано N из M», отдельный счётчик материалов; обновление сохраняет загруженные страницы и прокрутку.

Замер `query_records` (медиана 7 прогонов, SQLite 3.51.0, синтетические записи ~1 КБ текста, все совпадают с запросом — худший случай):

| Записей | Просмотр | Фильтр источника | Поиск | Поиск, 5-я страница |
|---|---|---|---|---|
| 1 000 | 1,7 мс | 0,9 мс | 11,6 мс | 10,3 мс |
| 10 000 | 1,6 мс | 5,8 мс | 78,0 мс | 79,4 мс |

Сниппеты FTS считаются отдельным запросом только для строк страницы (с ними в одном запросе было ~140 мс). Запрос остаётся в GUI-потоке; при 10 000 совпадений он близок к порогу 100 мс — асинхронный поиск с отбрасыванием устаревших ответов не сделан.

**T05 — правка.** `domain/transcript_edit.py` разбирает буфер без изменения результата и сообщает строку ошибки (битый/непоследовательный тайм-код, пустой буфер, текст до первой метки). `MainWindow._prepare_leave()` вызывается при открытии записи из библиотеки и Ctrl+K, новой записи и новом источнике, восстановлении версии и закрытии окна: правка сохраняется для своей записи; при ошибке разбора или записи пользователь остаётся на записи с текстом и видит причину, повторная попытка выполняется при следующем переходе. Отложенная версия сохраняется для записи, на которой была начата, и сбрасывается перед уходом. Черновик буфера автосохраняется через 1,5 с в `transcript_drafts` (миграция v10), после перезапуска предлагается как черновик и открывается в редакторе несохранённым; холостая правка версий не создаёт. Статус записи: «Сохранено в …» / «Черновик сохранён в …» / «✕ Не сохранено».

**T06 — монтаж.** `domain/cut_plan.py`: якорь — время, спикер, отпечаток текста + ревизия. Правка текста без изменения времени сохраняет выбор; split/merge, смена спикера или неоднозначность — «нужно проверить», исходное решение хранится до подтверждения. План в `cut_plans` (v11), undo/redo (кнопки и ⌘Z/⇧⌘Z) для флажков, «выбрать все/ничего», пауз и меню транскрипта. EDL и MP4 используют один `get_kept_segments()`; при «нужно проверить» экспорт спрашивает подтверждение.

**T07 — беседа.** `chat_messages` (v12): сообщения записи с ревизией, статусом `complete/cancelled/failed` и моделью. Беседа переключается по `record_id`, а не по тексту; старый воркер отменяется, поздние токены отсекаются счётчиком поколения. Правка расшифровки добавляет разделитель «ответы выше относятся к прежней версии». Прерванный ответ хранится как неполный и не идёт в контекст модели. При выключенной истории показано «беседа не сохраняется», в БД ничего не пишется. Добавлены экспорт в Markdown и очистка с удалением из истории.

**Миграции истории** v10–v12 только добавляют таблицы. Перед обновлением схемы существующей БД создаётся копия `history.sqlite3.v<N>.bak`. Удаление записи и «очистить всё» удаляют новые дочерние строки в той же транзакции.
